    OSRSClient Public API¶

    This site documents the public scripting / plugin API, exposed in two mirror forms:

    • C++ — srs::api::*, for plugins compiled against OSRSClient.lib. Headers live in OSRSClient/PluginAPI/API/. Plugins implement IScript (OSRSClient/PluginAPI/IScript.h) and call API methods, passing the ScriptContext& they receive in onLoad / pulse / onTick / onDraw.
    • Lua — srs.*, for .lua scripts loaded by the in-process Lua VM. Bindings live in OSRSClient/ScriptEngine/ScriptAPI.cpp. The host builds the ScriptContext internally; scripts just call srs.<module>.<method>(args).

    The two forms are at feature parity — every method documented here is callable from both C++ and Lua. Differences in shape (where unavoidable, e.g. Lua lacks pointer semantics) are called out per-method.

    Threading and spoofing contract

    All action-firing methods (interact, attack, click, cast, …) route through Interact on the engine main thread with always-on input spoofing. There is no escape hatch — calling DoAction from the render thread crashes, and the spoofer is fail-closed (if it can't inject, the action drops).

    Lifecycle¶

    C++ — IScript¶

    class IScript {
public:
    virtual const char* name() const = 0;
    virtual bool onLoad(const ScriptContext& ctx) = 0;
    virtual void onUnload() = 0;

    virtual void pulse  (const ScriptContext& ctx) {}  // per frame (~60Hz)
    virtual void onTick (const ScriptContext& ctx) {}  // per game tick (~600ms)
    virtual void onDraw (const ScriptContext& ctx) {}  // per frame, inside ImGui frame

    virtual void onSettingsChanged(const nlohmann::json& settings) {}
    virtual nlohmann::json schema() const { return {}; }
};

    Plugins export CreateScript / DestroyScript functions and ship as DLLs in the plugins/ directory.

    Lua — callback registration¶

    script.pulse(function() ... end)   -- per frame
script.onTick(function() ... end)  -- per game tick
script.draw(function() ... end)    -- per frame, inside ImGui frame

    script.draw is the only callback where srs.draw.* calls are valid — the host guarantees a live ImGui frame for it. pulse and onTick do not.

    pulse vs onTick¶

    Callback Cadence Use for
    pulse every rendered frame (~60 Hz) cheap state checks, per-frame visual work
    onTick every game tick (~600 ms) action firing, state-machine transitions

    The server can only process one action per tick, so per-frame action firing is wasted work that the spoofer will throttle. Move action logic to onTick and use pulse only for checks.

    Example — minimal Lua script¶

    -- Drop every shrimp the moment it lands in the backpack.
script.onTick(function()
    if srs.inventory.contains("Shrimps") then
        srs.inventory.dropAll("Shrimps")
    end
end)

script.draw(function()
    if srs.draw.beginAnchoredOverlay(
            "##fish-hud", 162, 32,
            srs.Corner.TopRight, -4, 4) then
        srs.draw.text("Caught: " .. srs.inventory.count("Shrimps"))
        srs.draw.endOverlay()
    end
end)

    Example — minimal C++ plugin¶

    class FishingPlugin : public IScript {
public:
    const char* name() const override { return "Fishing"; }
    bool onLoad(const ScriptContext&) override { return true; }
    void onUnload() override {}

    void onTick(const ScriptContext& ctx) override {
        using namespace srs::api;
        if (Inventory::contains(ctx, "Shrimps")) {
            Inventory::dropAll(ctx, "Shrimps");
        }
    }

    void onDraw(const ScriptContext& ctx) override {
        using namespace srs::api;
        if (Drawing::beginAnchoredOverlay(ctx, "##fish-hud",
                                          162, 32,
                                          Drawing::Corner::TopRight,
                                          -4, 4)) {
            Drawing::text("Caught: " + std::to_string(
                Inventory::count(ctx, std::string("Shrimps"))));
            Drawing::endOverlay();
        }
    }
};

extern "C" __declspec(dllexport) IScript* CreateScript()  { return new FishingPlugin(); }
extern "C" __declspec(dllexport) void DestroyScript(IScript* s) { delete s; }
