    NPC¶

    srs.npc

    Find NPCs in the scene and act on them. The srs.npc table carries both the finders (which NPCs are nearby) and the actions (attack, talk-to, …) so scripts can stay in one table.

    A target is identified by its spawn index + world coords. The finders return the ActionTarget usertype, and the action functions take one, so srs.npc.attack(npc) / npc:attack() work on whatever a finder handed you.

    All interact / attack / talkTo / bank / examine calls route through Interact, which always spoofs mouse motion + click before engine action dispatch (no escape hatch).

    Finding NPCs¶

    Method Lua
    All NPCs in scene srs.npc.all() → table
    By id srs.npc.byId(id) → table
    By name srs.npc.byName(name) → table
    Nearest (any) srs.npc.nearest() → ActionTarget \| nil
    Nearest by id srs.npc.nearestById(id) → ActionTarget \| nil
    Nearest by name srs.npc.nearestByName(name) → ActionTarget \| nil

    byName / nearestByName normalize the name internally (case- and whitespace-insensitive), so pass the in-game name as shown ("Banker", "Grand Exchange Clerk"). The srs.npc finders are the recommended going-forward form.

    Three equivalent finder surfaces

    Lua exposes the same finders three times — all hit the same backend, so pick whichever reads best and don't mix them for "different" results:

    Global npc.* srs.npc.* entity.*
    npc.all() srs.npc.all() entity.npcs()
    npc.byId(id) srs.npc.byId(id) entity.npcById(id)
    npc.byName(name) srs.npc.byName(name) entity.npcByName(name)
    npc.nearest() srs.npc.nearest() entity.nearestNpc()
    npc.nearestById(id) srs.npc.nearestById(id) —
    npc.nearestByName(name) srs.npc.nearestByName(name) —

    All return ActionTarget (lists or single-or-nil). The global npc table is a plain alias kept for source compatibility.

    Methods¶

    Method Lua
    Generic interact srs.npc.interact(target, action) → bool
    Option by position srs.npc.interactOp(target, op[, label]) → bool
    Attack srs.npc.attack(target) → bool
    Talk-to srs.npc.talkTo(target) → bool
    Bank (banker NPCs) srs.npc.bank(target) → bool
    Examine srs.npc.examine(target) → bool
    Still in world map srs.npc.isAlive(target) → bool
    Overhead prayer headicon srs.npc.overheadPrayer(target) → OverheadPrayer
    Overhead chat text srs.npc.overheadText(target) → string
    Spotanims (graphics) on the actor srs.npc.spotAnims(target) → table
    Has a spotanim id srs.npc.hasSpotAnim(target, id) → bool

    action is the exact menu-option string the game shows ("Attack", "Talk-to", "Bank", "Pickpocket", "Trade", "Steal-from", …). interactOp presses option op (1..5) of the NPC's menu by position instead of by text; any other op returns false. Use it for multi-state NPCs whose current options live on a varbit-selected child type — the parent type the game reports has no options at all, so interact("Start-trial") can't find the text and falls back to option 1. label is only used in logs (Lua: optional, defaults to "op<N>"). Like examine, interactOp is not an ActionTarget method — call srs.npc.interactOp(npc, 3).

    examine fires the right-click Examine and the engine prints the NPC's description to chat.

    overheadPrayer reads the NPC's protection-prayer headicon (live override when set, else the NpcType definition). Returns OverheadPrayer.None when the NPC shows no prayer icon or has despawned; only prayer-archive (440) icons are reported. See Prayer for the OverheadPrayer enum values — it's a Lua global enum, not under srs.npc.

    overheadText is the chat text drawn above the actor right now — NPC forced chat (an entling's "Short on top!", a Forester's shout) or a player's public chat — the same text the game draws over the head. Returns "" when nothing is shown, when the NPC has despawned, or when the text has expired (the engine clears it the tick its countdown reaches zero). Every finder result also carries an overheadText snapshot field plus overheadCycles (client ticks left before it clears); the method re-reads the live actor and is what to use when you hold an older target. Works for NPC and player targets.

    spotAnims lists the graphics playing on the actor right now: spell impacts, teleport flashes, boss charge-up effects. These are separate from tile graphics (GraphicsObjects) and in-flight Projectiles. An actor can carry several at once, each in its own slot. Each entry has:

    Field Notes
    slot 0–255. Slot 0 is the classic single "graphic"
    id Spotanim id. This client's cache id, the same id space as projectile/graphics-object id
    height Draw height offset
    startCycle Absolute client cycle (50 per second) the effect starts at
    delay Client cycles until it starts (0 once playing)
    active false while it is still waiting on its start delay

    The game drops each entry when its animation finishes, so the list only holds effects that are playing or about to start. It is empty when there are none. hasSpotAnim(target, id) is true for a pending effect as well, which lets you react to a boss charge-up before it plays. Both work for NPC and player targets and always read the live actor.

    local boss = srs.npc.nearestByName("Hunllef")
if boss then
    for _, g in ipairs(boss:spotAnims()) do
        print(("slot %d  id %d  active %s"):format(g.slot, g.id, tostring(g.active)))
    end
    -- boss:hasSpotAnim(id) is true from the moment the server queues it
end

    Spotanim events¶

    Method Lua
    Subscribe srs.npc.onSpotAnim(fn[, filter]) → token
    Unsubscribe srs.npc.offSpotAnim(token) → bool

    onSpotAnim fires once for every new spotanim the server puts on any NPC or player. It fires on the frame the update arrives, so you don't need to poll spotAnims(). That is when the effect is queued. If the server gave it a delay, it starts drawing delay client cycles later, so you can react before it is even on screen. Callbacks run on the script thread in the same per-frame pass as srs.hitsplats.onApplied, roughly 16 ms after the update arrives. Cleared slots are not reported.

    The callback receives a table:

    Field Notes
    id, slot, height As in spotAnims()
    delay Client cycles until it starts drawing (0 = right away)
    startCycle Absolute client cycle it starts at
    persist true if the game keeps it after its animation ends
    targetKind "npc", "player", "self" or "unresolved"
    isSelf true when it landed on you
    spawnIndex The actor's server index (−1 if unknown)
    npcId, name NPC id and name (npcId is −1 for players and "self"; name is "" for "self" and "unresolved")
    tileX, tileY, plane Where the actor stood. Left at 0 for "self" and "unresolved" (read srs.player for your own tile)
    wallClock Millisecond tick count when the update arrived (time since the system started, not a calendar time); use it for ordering and deltas
    target The live NPC ActionTarget (NPC targets only, else nil), so e.target:attack() works

    filter is optional. Pass a spotanim id (a number), or a table with any of id, npcId, spawnIndex and kind ("npc", "player" or "self"). Every field you give must match. The registration follows the same pause rules as pulse/onTick, and a script reload drops it.

    local BOSS_ID = 9021  -- placeholder: the boss's NPC id
local CHARGE = 1234   -- placeholder: the boss's charge-up spotanim id
local tok = srs.npc.onSpotAnim(function(e)
    print(("%s got spotanim %d, starts in %d cycles"):format(e.name, e.id, e.delay))
end, { npcId = BOSS_ID, id = CHARGE })
-- later: srs.npc.offSpotAnim(tok)

    isAlive semantics

    isAlive checks that the NPC is still present in the world. After an NPC dies it lingers a few ticks playing the death animation, then despawns — once that happens isAlive returns false. Currently does not treat HP-0-but-still-rendering as "dead"; callers that need that (loot timing, drop tracking) should poll currentHp via the NPCs panel column or entity.npcById(...).

    ActionTarget method-call shortcuts (Lua)¶

    The ActionTarget usertype exposes these as methods (use :):

    Method Lua
    Generic interact t:interact(action) → bool
    Attack t:attack() → bool
    Talk-to t:talkTo() → bool
    Bank t:bank() → bool
    Still in world map t:isAlive() → bool
    Overhead prayer headicon t:overheadPrayer() → OverheadPrayer
    Spotanims on the actor t:spotAnims() → table
    Has a spotanim id t:hasSpotAnim(id) → bool
    Handle still valid t:isValid() → bool

    For example:

    local npc = entity.nearestNpc()
if npc and npc:isAlive() then
    npc:attack()         -- == srs.npc.attack(npc)
    npc:talkTo()
    npc:bank()
    npc:interact("Pickpocket")
    npc:overheadPrayer() -- == srs.npc.overheadPrayer(npc)
    npc:spotAnims()      -- == srs.npc.spotAnims(npc)
    npc:hasSpotAnim(id)  -- == srs.npc.hasSpotAnim(npc, id)
end

    examine has no usertype shortcut

    examine is the one action not exposed as an ActionTarget method — there is no npc:examine(). Call srs.npc.examine(npc).

    Target fields¶

    Finders return the ActionTarget usertype. Its fields are read-only:

    Field Notes
    kind TargetKind enum (TargetKind.None / Npc / Player / Object / Tile)
    tileX, tileY, tileZ World tile coords
    plane 0..3
    spawnIndex Server-assigned spawn index
    entityId Item/Loc/Npc id depending on kind
    name Display name
    currentHp, maxHp Live HP (−1 = unknown; boss HP scaling is approximate)
    interactTarget Index of the actor this one is interacting with, within the kind given by interactTargetKind; -1 when not interacting
    interactTargetKind Kind of that target: 0 none, 1 NPC (interactTarget = NPC spawnIndex), 2 player (= player spawnIndex), 3 world entity. Always check the kind before comparing interactTarget
    animationId Active anim id
    modelMagnitude Engine getXYZMag half-extent (0 = unknown)
    overheadText Overhead chat text drawn right now ("" = none). Snapshot — see srs.npc.overheadText
    overheadCycles Client ticks until overheadText clears (0 = none)
    orientation Facing angle 0–2047, clockwise from south: 0 = S, 512 = W, 1024 = N, 1536 = E; −1 = unknown
    combatLevel Combat level (−1 = unknown)

    Defs

    For static NPC definition data (size, menu actions, max HP) see srs.defs in Defs.

    orientation / combatLevel semantics

    Both fields are populated for NPCs and players. orientation is the actor's target facing: the angle the engine turns toward, so it changes the tick the server sets it and the rendered model catches up over the next few ticks. Compare against the four cardinals with a tolerance (e.g. north = math.abs(o - 1024) <= 256) rather than exact equality if the NPC may be mid-turn. combatLevel is -1 for NPCs that show no level on the right-click (bankers, shopkeepers, pets).

    Example¶

    local npc = entity.nearestNpc()
if npc and npc:isAlive() then
    npc:attack()
end
