    Prayer¶

    srs::api::Prayer / srs.prayer

    Toggle prayers and read state. Backed by the prayer book widget (group 541) for clicks and per-prayer activation varbits for reads.

    Methods¶

    Method C++ Lua
    Remaining prayer points Prayer::points(ctx) → int32 srs.prayer.points() → int
    Base prayer level Prayer::level(ctx) → int32 srs.prayer.level() → int
    Display name Prayer::name(kind) → const char* srs.prayer.name(kind) → string
    Level requirement Prayer::levelRequired(kind) → int32 srs.prayer.levelRequired(kind) → int
    Activation varbit id Prayer::varbitId(kind) → int32 srs.prayer.varbitId(kind) → int
    Prayer book child id Prayer::widgetChild(kind) → int32 srs.prayer.widgetChild(kind) → int
    Per-prayer active state Prayer::isActive(ctx, kind) → bool srs.prayer.isActive(kind) → bool
    Is the varbit readable Prayer::isReadable(ctx, kind) → bool srs.prayer.isReadable(kind) → bool
    Every active prayer Prayer::activeList(ctx) → vector<PrayerKind> srs.prayer.activeList() → table
    Raw bitfield mirror Prayer::allActiveRaw(ctx) → int32 srs.prayer.allActiveRaw() → int
    Unlocked (Rigour etc.) Prayer::isUnlocked(ctx, kind) → bool srs.prayer.isUnlocked(kind) → bool
    Prayer occupying the slot Prayer::slotOccupant(ctx, kind) → PrayerKind srs.prayer.slotOccupant(kind) → int
    Usable right now Prayer::isAvailable(ctx, kind) → bool srs.prayer.isAvailable(kind) → bool
    Best damage prayer Prayer::bestOffensive(ctx, style) → PrayerKind srs.prayer.bestOffensive(style) → int
    Toggle prayer Prayer::toggle(ctx, kind) → bool srs.prayer.toggle(kind) → bool
    Ensure desired state Prayer::setActive(ctx, kind, on) → bool srs.prayer.setActive(kind, on) → bool
    • points and level pass through to existing GameData accessors so plugins don't need to import GameData.
    • isActive reads the prayer's own activation varbit. It returns false both for "off" and for "couldn't read" — use isReadable to tell those apart.
    • toggle clicks the prayer button to flip its state. It opens the Prayer tab first if needed, returning false that frame (the book doesn't render until the next one). It does not check prayer points, and it is unguarded: two calls in a tick flip the prayer twice.
    • setActive clicks only if currently mismatched, and is the call state-driven code should use — see the rate limit below.
    • activeList is one varbit read per prayer. That is the cheap "everything at once" read; the client's own bitfield mirror at varbit 4101 (PRAYER_ALLACTIVE) packs the same information, but its bit order isn't published by RuneLite, so it is exposed raw via allActiveRaw rather than decoded on a guess.

    setActive is rate-limited per prayer

    The activation varbit only flips once the server answers, up to a tick after the click. A caller polling at pulse rate therefore reads "still off" immediately after clicking and would click again, toggling the prayer straight back off — a live log showed two protects alternating every tick before the Gauntlet script added its own per-prayer gate. setActive now suppresses repeat clicks on the same prayer for 1200 ms (two game ticks) and returns false while it is waiting. toggle bypasses the gate.

    setActive also refuses — with a throttled log line — to click a prayer whose varbit can't be read at all, instead of clicking forever waiting for a flip that can never be observed.

    Constants¶

    PrayerKind constants (PrayerKind / srs.prayer.*):

    PrayerStyle constants — which line bestOffensive picks from: STYLE_MELEE, STYLE_RANGED, STYLE_MAGIC. They are prefixed because PrayerStyle::Melee is 0, the same int as PrayerKind::ProtectMagic.

    The book is not numbered in display order

    Children come from InterfaceID.Prayerbook.PRAYER1..PRAYER30 (child = 8 + N), and the ranged/magic prayers plus the later additions were appended as PRAYER19..PRAYER29. So Retribution (child 24) sits below Sharp Eye (child 27) in the numbering even though it is far below it in the book. Anything that guesses a child by counting rows will be wrong; the pairing comes from Microbot's Rs2PrayerEnum, and the three protects are live-verified against real DoAction captures.

    Eagle Eye / Deadeye and Mystic Might / Mystic Vigour share a button

    Deadeye replaces Eagle Eye in the book once unlocked, and Mystic Vigour replaces Mystic Might — one child, two prayers, two varbits. isActive is literal (it reads the prayer you asked about), slotOccupant tells you which of the pair the button currently activates, and isAvailable is false for the one that is currently shadowed. setActive(EAGLE_EYE, true) on an account with Deadeye unlocked refuses and logs, rather than clicking a button whose effect it can't observe.

    bestOffensive handles all of this — prefer it over naming a prayer directly when any account might run the script.

    Ruinous Powers

    The Ruinous Powers book (Varlamore) is a separate interface with its own prayers and its own bitfield mirror (varbit 14827). It is not covered by this module.

    Overhead prayers (headicons)¶

    srs::api::OverheadPrayer / Lua global OverheadPrayer

    The overhead protection-prayer headicon shown above an actor. In C++ this is a pure enum header (OverheadPrayer.h — no class, no export):

    enum class OverheadPrayer : int32_t {
    None = -1, Melee = 0, Missiles = 1, Magic = 2,
    Retribution = 3, Smite = 4, Redemption = 5
};

    In Lua the enum is registered at global scope — write OverheadPrayer.Missiles, not srs.prayer.OverheadPrayer (no such path exists).

    Value Name Meaning
    -1 None No headicon
    0 Melee Protect from Melee
    1 Missiles Protect from Missiles
    2 Magic Protect from Magic
    3 Retribution Retribution
    4 Smite Smite
    5 Redemption Redemption

    The numeric values are the engine's headicon prayer index, and they're identical for players and NPCs.

    Readers that return this enum:

    • Local player: Player::overheadPrayer(ctx) / srs.player.overheadPrayer() — see Player
    • NPCs: Npc::overheadPrayer(ctx, target) / srs.npc.overheadPrayer(target) — see NPC
    • Entity handle: target:overheadPrayer() on ActionTarget — see Entity

    Note these read the headicon, not the client's prayer-book state — isActive above is the local prayer-book read, overheadPrayer is what's actually displayed over a head (yours or an NPC's).

    Example¶

    using namespace srs::api;
if (Prayer::points(ctx) > 0) {
    Prayer::setActive(ctx, PrayerKind::ProtectMissile, true);
}

    if srs.prayer.points() > 0 then
    srs.prayer.setActive(srs.prayer.PROTECT_MISSILE, true)
end

    Picking a damage prayer without hard-coding one (Rigour on an account that has it, Eagle Eye on one that doesn't, nothing at all below level 8):

    using namespace srs::api;
const PrayerKind boost = Prayer::bestOffensive(ctx, PrayerStyle::Ranged);
if (boost != PrayerKind::None) Prayer::setActive(ctx, boost, true);

    local boost = srs.prayer.bestOffensive(srs.prayer.STYLE_RANGED)
if boost ~= srs.prayer.NONE then
    srs.prayer.setActive(boost, true)
end

    devscripts/verify_prayer_book.lua checks every entry in the table above against the live client: it dumps group 541, compares each child against the label the engine has there, then toggles every prayer the account can use and confirms the varbit follows the click both ways. Run it after any game update that moves interfaces.
