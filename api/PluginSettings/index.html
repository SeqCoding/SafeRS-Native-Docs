    PluginSettings¶

    srs::api::PluginSettings

    Write back to your plugin (or Lua script's) own schema-driven settings — the flat "<groupId>.<rowId>" values that back the schema returned by IScript::schema() / declared by script.declareSettings.

    Different from srs::api::Settings, which reads GAME settings (varbits / varps). This module is about the plugin/script's own UI values.

    Ctx-less by design — mirrors Lua's script.setSetting, which also takes no ctx. The write is attributed to the currently firing plugin (the one whose method is running on the calling thread). Meaningful during onSettingsButton / onSettingsChanged / pulse / onTick / onDraw; a call from outside a callback context is silently dropped.

    Methods¶

    Method C++ Lua
    Register a button handler PluginSettings::onButton(action, fn) → void script.onSettingsButton(name, fn)
    Write one flat setting PluginSettings::setValue(key, value) → void script.setSetting(key, value)

    The Lua bindings live in the script.* namespace since scripts already have a script global; C++ plugins reach the same behavior via the free functions above.

    Register from onLoad. onButton uses the same thread_local attribution as setValue, and onLoad runs with the plugin attributed. Registering elsewhere works too (any callback), but onLoad is the natural one-time home. fn is std::function<void(const std::string& action, const ScriptContext& ctx)>.

    ABI note. This is a registered-callback API (not an IScript virtual) specifically so adding it never shifted the IScript vtable. Plugins built against an older SDK header keep loading — they simply don't register any buttons. Extend IScript itself only by appending at the end.

    key is "<groupId>.<rowId>" — the same flat encoding onSettingsChanged receives. value may be any JSON-representable value that matches the row's kind: bool for check, number for number / slider, string for text / select. Written values persist per in-game character.

    Example — gear-setup capture button¶

    A button row + a text row let a plugin snapshot the currently worn gear into a textbox:

    #include "PluginAPI/API/PluginSettings.h"
#include "PluginAPI/API/Equipment.h"

class GearCapture : public IScript {
public:
    const char* name() const override { return "Gear Capture"; }
    void onUnload() override {}

    bool onLoad(const ScriptContext&) override {
        // Register the button handler once. Attribution is automatic —
        // onLoad runs with this plugin as the currently-firing one.
        srs::api::PluginSettings::onButton("pull_gear",
            [](const std::string& /*action*/, const ScriptContext& ctx) {
                std::string ids;
                for (auto& e : srs::api::Equipment::all(ctx)) {
                    if (!ids.empty()) ids += ',';
                    ids += std::to_string(e.id);
                }
                srs::api::PluginSettings::setValue("gear.ids", ids);
            });
        return true;
    }

    nlohmann::json schema() const override {
        return {{"groups", {{
            {"id", "gear"}, {"title", "gear setup"}, {"open", true},
            {"rows", {
                {{"id","ids"},  {"label","Equipped item ids"}, {"kind","text"},
                 {"value",""},  {"placeholder","click Pull to fill"}, {"mono", true}},
                {{"id","pull"}, {"label","Fill from worn gear"}, {"kind","button"},
                 {"value","Pull equipped"}, {"action","pull_gear"}},
            }}
        }}}};
    }
};

    script.declareSettings {
  groups = {
    { id = "gear", title = "gear setup", open = true, rows = {
      { id = "ids",  label = "Equipped item ids", kind = "text",
        value = "", placeholder = "click Pull to fill", mono = true },
      { id = "pull", label = "Fill from worn gear", kind = "button",
        value = "Pull equipped", action = "pull_gear" },
    }},
  },
}

script.onSettingsButton("pull_gear", function()
  local ids = {}
  for _, e in ipairs(srs.equipment.all()) do ids[#ids + 1] = e.id end
  script.setSetting("gear.ids", table.concat(ids, ","))
end)

    Threading¶

    Button clicks (and therefore PluginSettings::setValue calls made from inside onSettingsButton) run on the ScriptScheduler worker, never the render thread. A slow handler (item-name load, GE / bank calls) cannot freeze the game. Blocking primitives inside the handler release the GIL via the usual helpers so the render thread's onDraw / Lua script.draw keeps running smoothly.
