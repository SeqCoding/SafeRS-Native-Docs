    GraphicsObjects¶

    srs::api::GraphicsObjects / srs.graphicsObjects

    Read-only enumeration of tile-bound SpotAnims — falling debris during boss fights, acid pools (Vasa, Tekton), blood splatters, spell-impact tile effects, teleport sparkles, run-energy regen sparkles, and so on.

    Experimental — offset still being verified

    The container offset on WorldInstance isn't fully live-verified yet. The query methods return empty / nil until the offset is pinned for your client build — discover it at runtime with scan() and lock it in with setContainerOffset() (see Offset discovery). Treat every field except id as provisional.

    Methods¶

    Method C++ Lua
    All live gfx objects GraphicsObjects::all(ctx) → vector<GraphicsObjectEntry> srs.graphicsObjects.all() → table[]
    Filter by tile window GraphicsObjects::nearby(ctx, cx, cz, plane, radius) → vector<…> srs.graphicsObjects.nearby(cx, cz, plane, radius) → table[]
    Earliest-started entry GraphicsObjects::next(ctx) → optional<…> srs.graphicsObjects.next() → table \| nil

    nearby(cx, cz, plane, radius) returns entries whose tileX/tileZ are within Chebyshev distance radius of (cx, cz) on the given plane.

    next() returns the graphics object that will finish (disappear) soonest, or nil when none are active.

    Offset discovery¶

    Helpers for pinning the container offset on a new client build (see the warning above). Most scripts never need these.

    Method C++ Lua
    Probe candidate offsets GraphicsObjects::scan(ctx, base = 0) → vector<GraphicsObjectScanRow> srs.graphicsObjects.scan(base?) → table[]
    Pin the container offset GraphicsObjects::setContainerOffset(ctx, offset, base = 0) → bool srs.graphicsObjects.setContainerOffset(offset, base?) → bool
    Read the current offset GraphicsObjects::containerOffset(ctx) → int64 srs.graphicsObjects.containerOffset() → int
    Read the current base GraphicsObjects::containerBase(ctx) → int32 srs.graphicsObjects.containerBase() → int

    scan walks each WorldInstance (base = 0) or its Scene (base = 1) looking for a list shaped like the gfx-object container, returning one row per candidate. Pick the plausible row and pass its offset / base to setContainerOffset; the choice is session-persistent.

    GraphicsObjectScanRow:

    Field Type Notes
    offset int64 Base-relative offset probed
    base int 0 = WorldInstance, 1 = Scene
    entriesFound int64 Plausible entries at that offset
    shapeOk bool Begin/end looked like a sorted-set
    idsLookValid bool Entries had plausible spotanim ids
    firstId int A sample id, to recognize the effect

    Fields¶

    Each entry (Lua: plain table; C++: GraphicsObjectEntry):

    Field Type Notes
    id int SpotAnim cache id.
    animationId int The bound animation id (resolved from the spotanim's animation definition). Negative until the engine binds the animation.
    plane int 0..3
    tileX int World tile X.
    tileZ int World tile Y (Z in our naming).
    fineX int Engine sub-tile coordinate (localTileX * 128 + 64).
    fineY int Engine sub-tile coordinate.
    height int Height value relative to the tile.
    startCycle int The engine cycle at which this gfx began (or will begin) rendering. The gfx is in a "pending" state until currentCycle >= startCycle, then plays for the duration baked into its animation definition.
    framesSinceStart int currentFrame - startCycle. Negative while pending, positive while rendering. Not a lifetime countdown — the actual end is determined by the animation's own length.
    finished bool true once the engine has released the bound animation (the gfx is done playing and will be pruned on the next engine tick).

    Examples¶

    List active gfx near the player¶

    using namespace srs::api;
auto pos = Player::position(ctx);
auto nearby = GraphicsObjects::nearby(ctx, pos.x, pos.y, pos.plane, 5);
for (const auto& g : nearby) {
    // react to g.id / g.tileX / g.tileZ here
}

    local p = srs.player.position()
for _, g in ipairs(srs.graphicsObjects.nearby(p.x, p.y, p.plane, 5)) do
    log.info(string.format("gfx id=%d at (%d, %d)", g.id, g.tileX, g.tileZ))
end

    Dodge dangerous tiles¶

    A boss-mechanic dodger. Maintains a set of "lethal" spotanim ids and walks the player off any tile currently flagged as dangerous.

    -- Tune for the boss you're fighting.
local DANGEROUS_IDS = { [1448]=true, [1295]=true, [1259]=true }

script.onTick(function()
    -- Build the current dangerous-tile list from live gfx.
    local danger = {}
    for _, g in ipairs(srs.graphicsObjects.all()) do
        if DANGEROUS_IDS[g.id] and not g.finished then
            danger[#danger+1] = { x=g.tileX, y=g.tileZ, plane=g.plane }
        end
    end
    if #danger == 0 then return end

    local p = srs.player.position()
    local onDanger = false
    for _, d in ipairs(danger) do
        if d.plane==p.plane and d.x==p.x and d.y==p.y then
            onDanger = true; break
        end
    end
    if not onDanger then return end

    -- Find the closest walkable safe tile and walk there.
    local safe = game.findSafeTile(p.x, p.y, danger, 5)
    if safe then
        game.walkSmart(safe.x, safe.y, safe.plane)
        log.info(string.format("Dodging to (%d, %d)", safe.x, safe.y))
    end
end)

    See Walk for findSafeTile / walkSmart / walkFastCanvas documentation. Note game.findSafeTile (used above) is the Lua-side implementation on the global game table; the C++ facade counterpart is Walk::findSafeTile.

    React to a specific cast¶

    Wait until a particular spotanim id appears and react once it's been rendering for a few frames.

    local TARGET_ID = 1042   -- replace with the id you care about

script.onTick(function()
    for _, g in ipairs(srs.graphicsObjects.all()) do
        if g.id == TARGET_ID and g.framesSinceStart >= 0 and not g.finished then
            -- gfx is currently rendering — react now
            log.info(string.format("Target gfx active at (%d, %d)", g.tileX, g.tileZ))
            return
        end
    end
end)

    Notes¶

    • framesSinceStart is NOT a "time until removal" countdown. The engine prunes the gfx based on the animation's natural length, not from a counter on the gfx-object itself. Use finished to detect end-of-life.
    • fineX/fineY vs tileX/tileZ. Both are exposed for convenience. tileX/tileZ give world tile coordinates; fineX/fineY give the engine's sub-tile units (tile * 128 + 64). For tile-equality comparisons against Player.position(), use tileX/tileZ.
    • Pending gfx. When a spotanim has a start-delay in its packet (chained / sequenced effects), it appears in the list with framesSinceStart < 0 before it actually starts rendering. Filter on framesSinceStart >= 0 if you only care about currently-visible effects.
