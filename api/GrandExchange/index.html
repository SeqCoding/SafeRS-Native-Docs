    Grand Exchange¶

    srs::api::GrandExchange / srs.ge

    Read the player's 8 Grand Exchange offer slots and drive the GE interface. Mirrors Microbot's Rs2GrandExchange.

    Offer state is read live from the engine's offer array and works whether the GE window is open or closed (the RuneLite getGrandExchangeOffers analog) — no hook, no open window required. Interaction drives the GE's CS2 interface components (offer boxes, steppers, search box) plus the keyboard subsystem for exact numeric / item-name entry.

    Most interaction needs the GE open

    State reads (offers, offer, hasData, the slot predicates) work anywhere. Everything that clicks — createBuyOffer, buyItem, confirm, … — needs the Grand Exchange interface open first. Open it by interacting with a GE clerk: srs.npc.interact(clerk, "Exchange") (C++ Npc::interact).

    Blocking helpers

    buyItem / sellItem / setQuantity / setPrice / searchItem drive a multi-step flow with internal sleeps and keyboard entry. They block the calling script thread (up to a few seconds) and mute its pulse / onTick until they return. Blocking is safe — the DoAction is marshalled to the engine thread and keystrokes post asynchronously — but never call them from draw.

    State¶

    Valid GE open or closed. slot is 0..7.

    Method C++ Lua
    Any offer data resolved GrandExchange::hasData(ctx) → bool srs.ge.hasData() → bool
    All 8 slots GrandExchange::offers(ctx) → GeOfferInfo[8] srs.ge.offers() → table
    One slot GrandExchange::offer(ctx, slot) → GeOfferInfo srs.ge.offer(slot) → GeOfferInfo
    First empty slot (−1 if none) GrandExchange::firstEmptySlot(ctx) → int32 srs.ge.firstEmptySlot() → int
    Slot holding itemId (−1 if none) GrandExchange::slotOf(ctx, itemId) → int32 srs.ge.slotOf(itemId) → int
    Slot is buying/selling GrandExchange::isSlotActive(ctx, slot) → bool srs.ge.isSlotActive(slot) → bool
    Slot is finished/cancelled GrandExchange::isSlotFinished(ctx, slot) → bool srs.ge.isSlotFinished(slot) → bool
    Anything collectable GrandExchange::anyFinished(ctx) → bool srs.ge.anyFinished() → bool
    Every non-empty slot complete GrandExchange::allComplete(ctx) → bool srs.ge.allComplete() → bool

    Window state¶

    Method C++ Lua
    GE overview or setup open GrandExchange::isOpen(ctx) → bool srs.ge.isOpen() → bool
    Offer setup screen open GrandExchange::isOfferScreenOpen(ctx) → bool srs.ge.isOfferScreenOpen() → bool

    Collection & navigation¶

    Method C++ Lua
    Collect finished offers to inventory GrandExchange::collectToInventory(ctx) → bool srs.ge.collectToInventory() → bool
    Collect to bank (collection box only) GrandExchange::collectToBank(ctx) → bool srs.ge.collectToBank() → bool
    Open an active offer's detail screen GrandExchange::openSlot(ctx, slot) → bool srs.ge.openSlot(slot) → bool
    Abort an active offer (detail screen must be open) GrandExchange::abort(ctx, slot) → bool srs.ge.abort(slot) → bool
    Collect one box of the open detail screen GrandExchange::collectSlot(ctx, asNotes = true) → bool srs.ge.collectSlot([asNotes=true]) → bool
    Close the GE window GrandExchange::close(ctx) → bool srs.ge.close() → bool
    Compat no-op — always false GrandExchange::back(ctx) → bool srs.ge.back() → bool

    collectToInventory prefers the GE-screen "Collect to inventory" button and falls back to the standalone collection box. abort requires the offer's detail screen open first (openSlot(slot), wait a tick) — the "Abort offer" button lives on the detail screen, not the overview. It dispatches the capture-verified CC_OP (widget 465:23, sub-op 0, action index 1); a real-input click on that button silently no-ops.

    collectSlot collects one box of the open detail screen per call — the items box or the coins box (refund after an abort, or sale proceeds). It reads the box's own op list and prefers Collect-notes for unstackables when asNotes is true (default), so bought items land in the backpack as a single noted stack; the coins box uses its captured op 2. Call it every tick until offer(slot) reads Empty — the engine drops back to the overview by itself once the slot is drained. Returns false when nothing collectable is shown (detail screen not open, or already empty).

    -- Abort a stalled buy, then take the refund + partial fill.
if srs.ge.isSlotActive(slot) then
    srs.ge.openSlot(slot)             -- tick 1: detail screen
    -- tick 2:
    srs.ge.abort(slot)
else
    -- tick 3+: slot is Cancelled — drain it
    if srs.ge.offer(slot).state ~= srs.ge.State.Empty then srs.ge.collectSlot() end
end
``` There is no "back" button
on the native GE — the engine returns to the overview automatically after
confirm / abort / collect, so `back()` exists only for API compatibility and
always returns `false`; use `close()` to leave.

## Offer setup (low-level)

The step-by-step path. Most scripts want `buyItem` / `sellItem` instead.

| Method | C++ | Lua |
| --- | --- | --- |
| Start a BUY on an empty box; opens setup + search | `GrandExchange::createBuyOffer(ctx, slot) → bool` | `srs.ge.createBuyOffer(slot) → bool` |
| Start a SELL on an empty box — [UNVERIFIED] | `GrandExchange::createSellOffer(ctx, slot) → bool` | `srs.ge.createSellOffer(slot) → bool` |
| Pick a SELL item from the side inventory | `GrandExchange::setOfferItem(ctx, invSlot, itemId) → bool` | `srs.ge.setOfferItem(invSlot, itemId) → bool` |
| Quantity +1 / +10 / +100 / +All | `GrandExchange::addQuantity1\|10\|100\|All(ctx) → bool` | `srs.ge.addQuantity1\|10\|100\|All() → bool` |
| Open the exact-quantity chatbox prompt | `GrandExchange::promptQuantity(ctx) → bool` | `srs.ge.promptQuantity() → bool` |
| Price −5% / −1% / +1% / +5% | `GrandExchange::decreasePrice5pct \| decreasePrice1pct \| increasePrice1pct \| increasePrice5pct(ctx) → bool` | `srs.ge.decreasePrice5pct \| … () → bool` |
| Open the exact-price chatbox prompt | `GrandExchange::promptPrice(ctx) → bool` | `srs.ge.promptPrice() → bool` |
| Confirm the offer being set up | `GrandExchange::confirm(ctx) → bool` | `srs.ge.confirm() → bool` |

!!! warning "createSellOffer is [UNVERIFIED]"
    A SELL offer is begun by clicking the item in the GE side inventory
    (`setOfferItem`, group 467), not by an empty-box action.
    `createSellOffer(ctx, slot)` exists for API symmetry but fires the
    unverified op-4 box action (`kOp_CreateSell`), which may be a no-op —
    `sellItem` does **not** use this path. Prefer `sellItem` /
    `setOfferItem`.

## Exact entry & search (blocking)

| Method | C++ | Lua |
| --- | --- | --- |
| Type an exact quantity into the prompt | `GrandExchange::setQuantity(ctx, quantity) → bool` | `srs.ge.setQuantity(quantity) → bool` |
| Type an exact price into the prompt | `GrandExchange::setPrice(ctx, price) → bool` | `srs.ge.setPrice(price) → bool` |
| Type an item name into the buy-search box | `GrandExchange::searchItem(ctx, itemName) → bool` | `srs.ge.searchItem(itemName) → bool` |

These open the relevant chatbox prompt, type the value with human-paced
timing, wait for the input queue to drain, and (for numbers) submit with
Enter. `searchItem` populates the result list but does **not** pick a result —
use `buyItem` for the full flow.

## One-call offers (blocking)

The high-level surface — find a slot, select the item, set quantity + price,
confirm, all in one call. The GE offer screen must already be open.

| Method | C++ | Lua |
| --- | --- | --- |
| Place a complete buy offer | `GrandExchange::buyItem(ctx, itemId\|name, quantity, price) → bool` | `srs.ge.buyItem(itemId\|name, quantity, price) → bool` |
| Place a complete sell offer | `GrandExchange::sellItem(ctx, itemId\|name, quantity, price) → bool` | `srs.ge.sellItem(itemId\|name, quantity, price) → bool` |

Both accept either an item id (number) or a display name (string) as the first
argument. `price` is gp-per-item; pass `<= 0` to leave the engine's default
guide price untouched. `quantity` must be `> 0`. `buyItem` types the name into
the search box and selects the match (the by-id form resolves the display name
via the live item cache); `sellItem` requires the item in your backpack and
picks its slot automatically. Returns `true` only if the flow ran through
Confirm.

For sensible prices, pair these with the [market-price helpers](GePrices.md) on
the same `srs.ge` table — e.g. `srs.ge.buyItem(id, qty, srs.ge.buyPrice(id))`.

## Types

**`GeOfferInfo`** — one offer slot. Fields are read-only; the `is*` helpers are
callable in both C++ and Lua (`offer:isFinished()`).

| Field | Type | Meaning |
| --- | --- | --- |
| `slot` | int32 | Slot index 0..7 (−1 if invalid) |
| `state` | GeState | Lifecycle (see below) |
| `itemId` | int32 | Traded item id (−1 if empty) |
| `totalQuantity` | int32 | Offer size |
| `quantityDone` | int32 | Bought / sold so far |
| `price` | int32 | Price per item on the offer |
| `spent` | int64 | gp moved so far |

Helpers: `isEmpty()`, `isActive()`, `isComplete()`, `isFinished()`.

**`GeState`** (`GeState` / `srs.ge.State.*`):

| Const | Value | Meaning |
| --- | --- | --- |
| `Empty` | 0 | Slot unused |
| `CancelledBuy` | 1 | Buy aborted |
| `CancelledSell` | 2 | Sell aborted |
| `Buying` | 3 | Active buy |
| `Bought` | 4 | Buy complete |
| `Selling` | 5 | Active sell |
| `Sold` | 6 | Sell complete |

!!! note "Terminal states are best-effort"
    `Empty` / `Buying` / `Selling` are read directly from the live offer array.
    The terminal bytes (`Bought` / `Sold`, and the cancelled split) are
    best-effort decodes — gate on `isFinished()` / `anyFinished()` rather than a
    specific terminal value where you can.

## Example

```lua
-- Buy 1000 nature runes at the instant-buy price, then collect when done.
local NATURE = 561
script.onTick(function()
    if not srs.ge.isOpen() then return end          -- open via the clerk first
    if srs.ge.slotOf(NATURE) < 0 and srs.ge.firstEmptySlot() >= 0 then
        srs.ge.buyItem(NATURE, 1000, srs.ge.buyPrice(NATURE))
    elseif srs.ge.anyFinished() then
        srs.ge.collectToInventory()
    end
end)
