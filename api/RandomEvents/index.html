    RandomEvents¶

    srs::api::RandomEvents / srs.randomEvents

    The client runs a random-event handler on its own, for every script — no script needs event logic of its own. Settings are per account and are edited in the launcher only; scripts cannot change them. Scripts can pause the handler for a stretch and read its state.

    What the handler does¶

    • It watches for a random-event NPC that is targeting your player (another player's event is ignored). Event NPCs are recognised by id for the common events (Genie, Dr Jekyll, Drunken dwarf, Evil Bob, Rick Turpentine, Mysterious Old Man, Pillory guard, Sandwich lady and the rest), and by having a "Dismiss" option.
    • After a short random delay (a few game ticks, so it doesn't react on the spawn tick) it dismisses the NPC.
    • Genie: if the account has a lamp skill set in the launcher, the handler talks to the Genie, takes the lamp, uses it, and picks that skill. With no lamp skill set, the Genie is simply dismissed.
    • By default it only acts while a script or plugin is enabled; a human playing by hand handles their own events. It also only acts while logged in and the break scheduler is running or idle.

    Methods¶

    Description C++ Lua
    Pause handling RandomEvents::suspend() srs.randomEvents.suspend()
    Resume handling RandomEvents::resume() srs.randomEvents.resume()
    Is handling paused by a script? RandomEvents::isSuspended() → bool srs.randomEvents.isSuspended() → bool
    Is the handler acting right now? RandomEvents::isHandling() → bool srs.randomEvents.isHandling() → bool
    Current phase RandomEvents::phase() → string srs.randomEvents.phase() → string
    Account's lamp skill ("" = Genie is dismissed) RandomEvents::lampSkill() → string srs.randomEvents.lampSkill() → string
    Is handling enabled for this account? RandomEvents::isEnabled() → bool srs.randomEvents.isEnabled() → bool
    Events handled since the client started RandomEvents::handledCount() → int32 srs.randomEvents.handledCount() → int

    suspend() lasts until resume() is called, or until no script or plugin is enabled any more (the override is then cleared). It does not change the account's saved settings.

    isHandling() is true while an event is being dismissed, talked to, or its lamp used. While it is true your pulse / onTick callbacks are not called at all, so a script's click can't land on top of the handler's. The short reaction delay before the handler acts (phase Waiting) does not pause your script.

    Phases¶

    phase() returns one of:

    Value Meaning
    Idle Nothing to do
    Waiting Event detected, sitting out the reaction delay
    Dismissing Dismissing the NPC
    TalkingGenie Talking to the Genie
    RubbingLamp Using the lamp
    ChoosingSkill Picking the skill on the lamp interface

    Example¶

    -- Don't let the handler interrupt a boss fight
script.onTick(function()
    if inBossFight() then
        if not srs.randomEvents.isSuspended() then srs.randomEvents.suspend() end
    elseif srs.randomEvents.isSuspended() then
        srs.randomEvents.resume()
    end
end)

    Always resume

    A suspended handler ignores events until you call resume() (or all scripts stop). Don't leave it suspended longer than necessary.

    Settings are launcher-only

    Enabled, reaction delay, Genie handling and the lamp skill are per-account settings in the launcher. lampSkill() and isEnabled() only report them.
