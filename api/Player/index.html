    Player¶

    srs::api::Player / srs.player

    Local-player state. Thin wrappers over GameData getters. Each helper returns a sensible fallback (empty string / -1 / 0) instead of optional so Lua callers don't have to deal with a multi-return shape.

    Detail¶

    • position — returns {0, 0, 0} when GS or the player struct isn't resolved (pre-login). Callers that care about the difference should check World::getId(ctx) >= 0 first. Inside an instance this is the raw instance-local tile.
    • templatePosition — same as position outside an instance; inside an instance it maps the raw instance-local tile back through the engine's chunk layout to the template world tile (the wiki / RuneLite / Microbot coordinate), falling back to position when the conversion can't be made. Pairs with srs.area.isInInstance() to decide raw-vs-template coordinates in instanced content.
    • displayName — empty string pre-login. Resolved via WI-map (GS+0xCA40 → WorldInstance → PlayerSubMap.find(LocalPlayerIndex)) in patch 238+.
    • animation — current animation id from the active AnimSlot. -1 = idle.
    • weight — reads VarPlayer 169.
    • runEnergy — in 0..10000 range (raw network units; divide by 100 for the displayed percentage). -1 if GS isn't resolved.
    • idleTicks — number of consecutive game ticks the player's active animation has been -1. Reset to 0 the moment any non-idle animation plays. Maintained by GameData::onTick.
    • skillLevel / skillBase / skillXp — read the boosted level, base level, or total XP for any skill. Returns 0 when GS isn't resolved.
    • hitpoints / maxHitpoints — shorthand for skillLevel(Skill::Hitpoints) / skillBase(Skill::Hitpoints).
    • prayer / maxPrayer — current prayer points (live, drains with use) + base prayer level. Mirrors srs::api::Prayer::points / Prayer::level.
    • overheadPrayer — the local player's active Protect-from headicon. OverheadPrayer.None when no overhead prayer is active or pre-login. See Prayer for the OverheadPrayer enum (a Lua global enum — same values for players and NPCs; NPCs read it via Npc::overheadPrayer).
    • questState — completion bucket for a quest (NotStarted / InProgress / Finished). Backed by the engine's QUEST_STATUS_GET clientscript (CS2 4029) — the same source RuneLite/Microbot use — so it is correct for every quest with no hand-maintained thresholds. The script must run on the engine thread while scripts run on the render thread, so the value is cached and refreshed asynchronously on the engine thread (EngineDispatch's non-click work lane, drained on every outbound packet): the first lookup of a given quest returns QuestState::Unknown and kicks off a refresh that lands within a tick or two on its own — no click needed, then stays live. Poll until != Unknown, or just read it each tick. Subsequent reads are instant.
    • questProgress — the raw varbit/varp that increments as a quest advances (RuneLite QuestVarbits / QuestVarPlayer) — i.e. the step number a questing script wants. Thread-safe and instant (a plain var read, no clientscript). 0 before the quest is started; quest-specific value as it advances; -1 for the handful of quests with no single tracked progress var, or when VarpSystem isn't ready. Use questState for completion; use this for "which step am I on".

    Types¶

    WorldTile (read-only):

    Field Type
    x int32
    y int32
    plane int32

    No Lua constructor

    WorldTile is a read-only usertype with no Lua constructor — scripts obtain one from srs.player.position() (or another API that returns tiles). Every Lua API that takes a tile also offers (x, y[, plane]) overloads (e.g. srs.camera.rotateToTile(x, y)), so you never need to build one.

    Skill enum — values match the engine's skill table:

    Attack, Defence, Strength, Hitpoints, Ranged, Prayer, Magic, Cooking, Woodcutting, Fletching, Fishing, Firemaking, Crafting, Smithing, Mining, Herblore, Agility, Thieving, Slayer, Farming, Runecraft, Hunter, Construction, Sailing.

    In Lua: Skill.Hitpoints, etc. (registered at Lua global scope, same as CameraMode).

    Quest enum — every quest the engine tracks (209 generated enumerators, identical in C++ and Lua), value = stable index. Names + the underlying quest-config struct ids are ported from RuneLite's Quest enum (via Microbot's bundled Quest Helper). Examples: Quest.CooksAssistant, Quest.DragonSlayerI, Quest.MonkeyMadnessIi, Quest.RecipeForDisaster, Quest.DesertTreasureIiTheFallenEmpire. Registered at Lua global scope (same as Skill). Regenerate after a game update with tools/gen_quest_sources.py (sourced from tools/quest_table.txt).

    QuestState enum:

    Value Meaning
    Unknown Not cached yet — questState hasn't primed for this quest. Sentinel; never returned by the engine
    NotStarted Quest not begun
    InProgress Quest started, not finished
    Finished Quest complete

    In Lua: QuestState.Finished, etc. (registered at Lua global scope).

    Example¶

    using namespace srs::api;
auto pos = Player::position(ctx);
if (Player::hitpoints(ctx) < Player::maxHitpoints(ctx) / 2) {
    Food::eatBest(ctx);
}
if (Player::idleTicks(ctx) > 5 &&
    Player::overheadPrayer(ctx) == OverheadPrayer::None) {
    // idle and no protection up — do something
}

    local pos = srs.player.position()
log.info(("at %d, %d (plane %d)"):format(pos.x, pos.y, pos.plane))
if srs.player.hitpoints() < srs.player.maxHitpoints() / 2 then
    srs.food.eatBest()
end
if srs.player.questState(Quest.CooksAssistant) == QuestState.Finished then
    log.info("Cook's Assistant done")
end
