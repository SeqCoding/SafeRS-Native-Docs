    Events¶

    srs.events (Lua)

    A central registry for engine events. Subscribe a callback to a named event and it fires once per occurrence, delivered on the script thread with a single payload table. This is the general-purpose counterpart to the dedicated srs.chat.onMessage / srs.projectiles.onSpawned streams — one on(name, fn) entry point for the rest of the engine's events.

    Fires for everyone, not just you

    Like chat and projectiles, an event fires for every matching occurrence in the scene (e.g. any NPC's hit, any tracked skill's XP), not only ones involving the local player. Filter inside your handler, or pass the optional id filter (below).

    Delivery thread

    Callbacks run on the script (worker) thread, drained once per frame (~16 ms), so it is safe to call the rest of the srs.* API from them. A producer on the game/render thread queues the event; the queue is bounded (oldest dropped under a sustained flood). Per-script pause applies — a paused/disabled script stops receiving events; a script inside srs.wait still receives them (events are informational).

    Methods¶

    Method Lua
    Subscribe srs.events.on(name, fn) → token
    Subscribe with id filter srs.events.on(name, id, fn) → token
    Unsubscribe srs.events.off(token) → bool

    name must be one of the event catalog constants (also in srs.events.EVENTS). An unknown name raises an error — this is deliberate typo protection, so a mistyped event name fails loudly at on() instead of silently never firing. off(token) is safe to call from inside a firing callback; a full script reload clears all subscriptions automatically.

    The optional middle id argument filters by the event's primary id (see each event below) — e.g. only a specific skill's XP, or (once wired) a specific varbit.

    Event catalog¶

    srs.events.EVENTS exposes the valid names as constants, e.g. srs.events.EVENTS.XP_GAINED == "xpGained". Every payload table also carries an event field (the name) so one handler can dispatch on multiple subscriptions.

    Catalog

    Every event listed below is live. srs.events.EVENTS holds the name constants. Subscribing to a name not in the catalog raises an error (typo protection), as does subscribing to "varbitChanged" without an id.

    "xpGained"¶

    Fires when a skill's experience increases. The optional id filter is the skill index (see Skill).

    Field Type Notes
    event string "xpGained"
    skill int Skill index
    xp int New total experience for the skill
    gained int Experience delta since the previous tick (> 0)
    level int Current (real) level of the skill
    wallClock number GetTickCount64() at capture

    "levelUp"¶

    Fires when a skill's real level increases (a genuine level-up, not a boost). The optional id filter is the skill index.

    Field Type Notes
    event string "levelUp"
    skill int Skill index
    level int New level
    previousLevel int Level before the gain
    wallClock number GetTickCount64() at capture

    No spurious burst on login

    The tick-diff producers (xpGained, levelUp, inventoryChanged, npcSpawned / npcDespawned) prime their baseline silently on the first tick they see (and whenever you are logged out), so logging in does not fire an event for every skill / item / on-screen NPC — only genuine changes observed while logged in are delivered.

    "inventoryChanged"¶

    Fires when your backpack contents change, as a net quantity delta per item id (aggregated across slots, so it is robust to items being reordered between slots — one event per changed item id per tick, not per slot). Optional id filter = item id.

    Field Type Notes
    event string "inventoryChanged"
    itemId int The item whose total quantity changed
    quantityDelta int Net change (> 0 gained, < 0 lost)
    container int Inventory container id (93)
    slot int -1 — aggregate event, not a per-slot notification
    wallClock number GetTickCount64() at capture

    "varbitChanged" — id filter required¶

    Fires when a watched varbit's value changes. You must pass the varbit id — srs.events.on("varbitChanged", varbitId, fn); an unfiltered subscription is rejected (the varp storm makes a firehose impractical). Only the varbit ids you subscribe to are polled, on the script thread.

    Field Type Notes
    event string "varbitChanged"
    id int The varbit id
    value int New value
    previousValue int Value before the change
    wallClock number Capture time

    "npcSpawned" / "npcDespawned"¶

    Fire when an NPC enters / leaves the loaded scene. Optional id filter = the NpcType definition id (only that NPC type).

    Field Type Notes
    event string "npcSpawned" or "npcDespawned"
    index int Server spawn index — opaque, and may be reused after despawn
    id int NpcType definition id
    name string Display name (may be empty mid-load)
    wallClock number Capture time

    Note

    A spawn index reused within a single tick for a different NPC id is reported as a despawn of the old followed by a spawn of the new.

    "hitsplat"¶

    Fires for every hitsplat applied to any actor — you or others. Optional id filter = hitType.

    Field Type Notes
    event string "hitsplat"
    hitType int Engine hit-type (0 corruption, 2 poison, 5 venom, 12 block, 16 damage, 18 shield, …)
    amount int Damage (0 for block / miss)
    soakType int Soak type (-1 = none)
    targetKind int 1 = local player (you), 0 = other actor
    wallClock number Capture time

    Use srs.hitsplats for the full feed

    This is a cut-down view. srs.hitsplats carries the same splats with the exact victim resolved (name, NPC id, spawn index, tile, and a live ActionTarget), the game tick, and polling reads (recent / onSelf / onTarget) for scripts that don't want an event handler.

    hitType names are provisional

    The type ids above have not been confirmed against a live capture — branch on the raw number and log it. amount is unaffected and reliable.

    Example¶

    -- Track XP/hr for Woodcutting and shout on a level-up.
local WOODCUTTING = Skill.Woodcutting   -- skill index (see Globals)
local session = 0

-- Filtered subscription: only Woodcutting XP reaches this handler.
srs.events.on(srs.events.EVENTS.XP_GAINED, WOODCUTTING, function(e)
    session = session + e.gained
    log.info(("+%d wc xp (%d total this run)"):format(e.gained, session))
end)

-- Unfiltered: any skill's level-up.
local tok = srs.events.on("levelUp", function(e)
    log.info(("LEVEL UP! skill %d is now %d"):format(e.skill, e.level))
    -- e.event == "levelUp"
end)

-- ... srs.events.off(tok) to stop listening early (optional; reload clears it).
