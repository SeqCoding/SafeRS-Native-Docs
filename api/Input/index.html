    Input¶

    srs::api::Input / srs.input

    Keyboard primitives. Two families live here, and they take different roads into the engine:

    Family Road Reaches
    typeString, pressKey, pressEnter, pressEscape the engine's own InputEventManager (the keyPressed / keyChar / keyReleased trio a real key press posts), marshalled onto the render thread in-game text fields (chatbox prompts, GE search, display-name box, public chat) and the engine's keybinds
    keyTap / osKeyTap / isKeyPending raw WM_KEYDOWN / WM_KEYUP to the game's window procedure camera / movement keys held for a duration

    Both are per-window and focus-independent: they work while the client is backgrounded and with several clients running. Nothing here uses SendInput.

    The WndProc road does not type text in-game

    Since build 238.5 the engine gates the synthetic WM_CHAR path to real OS input, so a WndProc keystroke never lands in an in-game text field. Use typeString / pressEnter for anything with a text box, and keep keyTap for what it was built for: holding arrow keys for the camera.

    Not on the login screen

    The engine-queue road feeds the logged-in input pipeline only. On the title / login screen typeString and pressKey do nothing; credential entry is handled inside the break manager and is deliberately not reachable from scripts.

    Methods¶

    Method C++ Lua
    Type text into the focused field (blocks) Input::typeString(ctx, text) → size_t srs.input.typeString(text) → int
    Type, then Enter (blocks) Input::typeString(ctx, text, submit) → size_t srs.input.typeString(text, submit) → int
    Type with a custom pacing band (blocks) Input::typeString(ctx, text, submit, minMs, maxMs) → size_t srs.input.typeString(text, submit, minMs, maxMs) → int
    Tap one key, engine road (fire-and-forget) Input::pressKey(ctx, vk) → bool srs.input.pressKey(vk) → bool
    Enter / Escape, engine road Input::pressEnter(ctx) → bool / Input::pressEscape(ctx) → bool srs.input.pressEnter() → bool / srs.input.pressEscape() → bool
    Tap a key, WndProc road — srs.input.keyTap(vk, holdMs)
    Tap a key (deprecated alias of keyTap) — srs.input.osKeyTap(vk, holdMs)
    Any WndProc release still scheduled? — srs.input.isKeyPending() → bool

    typeString¶

    Types text into whatever engine text field currently has keyboard focus. It opens and focuses nothing: fire the thing that opens the field first (a Withdraw-X click, a door, an NPC line), wait for it to render, then type. Text typed while no field has focus is silently swallowed by the engine. For the chatbox prompt use srs.dialogue.enterText / enterAmount (or srs.prompt.*), which wait for the prompt before typing.

    • Pacing. The gap between characters is drawn per character from [minMs, maxMs], default 80–160 ms — a hand, not a metronome.
    • Blocking. The calling script sleeps until the whole string has drained and settled: roughly #text × 120 ms + 300 ms, plus 250 + 300 ms when submit is true. Call it from pulse / onTick, never from draw, and call it once per field — not every tick.
    • Return value is the number of characters queued. Characters with no Windows virtual-key mapping (most non-ASCII) are skipped; the count tells you. With submit = true the Enter is sent even when the count is 0.
    • Case and shifted symbols come through verbatim: the character event carries the literal character.

    pressKey / pressEnter / pressEscape¶

    One non-character key through the engine road. vk is a Win32 virtual-key (0x0D Enter, 0x1B Escape, 0x09 Tab, 0x08 Backspace, 0x20 Space, digits and letters). Fire-and-forget: true means dispatched, not that the field reacted. pressEscape is the way to dismiss a chatbox prompt a script does not want to answer; pressEnter submits a field you typed into without submit.

    keyTap vs osKeyTap¶

    There is one WndProc path: keyTap posts WM_KEYDOWN now and schedules the WM_KEYUP for holdMs later (holdMs < 0 clamps to 0). The release fires from InputManager::update() every rendered frame (~16 ms granularity). osKeyTap is a deprecated alias that forwards to keyTap — it no longer uses SendInput and has no foreground requirement; it is kept only so older ported scripts keep compiling.

    VK constants¶

    srs.input.VK.*:

    Name Value VK
    LEFT 0x25 VK_LEFT
    UP 0x26 VK_UP
    RIGHT 0x27 VK_RIGHT
    DOWN 0x28 VK_DOWN
    SPACE 0x20 VK_SPACE
    ENTER 0x0D VK_RETURN
    ESCAPE 0x1B VK_ESCAPE
    TAB 0x09 VK_TAB
    BACKSPACE 0x08 VK_BACK

    For other keys pass the raw VK integer (see Microsoft's Virtual-Key Codes).

    Examples¶

    using namespace srs::api;

// Custom-quantity withdraw: withdrawX runs the whole Enter-amount prompt
// itself (click, wait for the prompt, type, Enter) for any amount other
// than 1/5/10 — no manual typing needed. amount <= 0 returns false.
Bank::withdrawX(ctx, "Coins", 1337);

// typeString is for fields you open yourself: fire the trigger, wait for
// the prompt, then type + Enter.
if (Prompt::waitOpen(ctx)) {
    Input::typeString(ctx, "1337", /*submit*/ true);
}

    -- Tutorial Island display-name box (widget 558): focus it, type, then
-- press the "Set name" button. Once — not every tick.
if srs.widget.isOpen(558) and not typedName then
    srs.widget.clickReal(558, 7)              -- the NAME box
    local n = srs.input.typeString("kebab" .. math.random(100, 999))
    typedName = n > 0
    srs.widget.click(558, 19, "Set name")
end

-- Public chat: type and send in one call.
srs.input.typeString("gz", true)

    -- Calibrate yaw-rotation rate (WndProc road): hold left arrow for 1s.
local y0 = srs.camera.getYaw()
srs.input.keyTap(srs.input.VK.LEFT, 1000)
script.nextTick(function()
    local y1 = srs.camera.getYaw()
    log.info(("Δyaw over 1s = %d units"):format((y1 - y0) % 2048))
end)
