    Bank¶

    srs::api::Bank / srs.bank

    Full bank workflow: navigation to named banks, opening / closing, tab switching, per-item withdraw + deposit, bulk deposit, scrolling, and the "1 / 5 / 10 / X / All" quantity preset. Constants lifted from RuneLite (InterfaceID.Bankmain, VarbitID.BANK_*, ScriptID.UPDATE_SCROLLBAR).

    State¶

    Method C++ Lua
    Is bank open Bank::isOpen(ctx) → bool srs.bank.isOpen() → bool
    Is bank PIN open Bank::isPinOpen(ctx) → bool srs.bank.isPinOpen() → bool
    Is a banker NPC nearby Bank::isBankerNearby(ctx) → bool srs.bank.isBankerNearby() → bool

    Bank PIN¶

    Auto-enter the bound account's 4-digit PIN on the keypad. The PIN itself is stored in the launcher's per-account encrypted record (DPAPI, user-scope) and never crosses the script API boundary — handleBankPin takes no PIN argument and hasBoundBankPin only exposes a boolean. The DLL leases the PIN through osrs::breakmgr::CredentialStore::leaseBankPin(), dispatches four CC_OP (slot 57) clicks on the keypad widgets in group 213, and zeros the buffer before returning.

    Method C++ Lua
    Auto-enter the PIN Bank::handleBankPin(ctx) → bool srs.bank.handleBankPin() → bool
    Has a PIN been bound Bank::hasBoundBankPin() → bool srs.bank.hasBoundBankPin() → bool

    Per-digit flow (mirrors Microbot's Rs2Bank.handleBankPin):

    1. Poll widget (213, 10) for the instruction text ("FIRST digit", "SECOND digit", "THIRD digit", "FOURTH digit") — up to 2 s.
    2. Scan group 213 for a widget whose text equals the digit char.
    3. Fire CC_OP at that widget through Interact::performWidget — packet + mouse spoof, same dispatch path as every other Bank click.
    4. Sleep ~250 ms for the engine to advance the instruction widget.

    Return values:

    • true — PIN widget isn't open (no-op) or all 4 digits dispatched.
    • false — no account bound, account has no PIN, instruction text didn't appear within 2 s, the digit widget can't be found in group 213, or the click dispatch was refused.

    Blocking: up to ~8 s per call (4 × 2 s instruction timeout). Call from a script tick — never from the render thread.

    if srs.bank.isPinOpen() then
  if not srs.bank.handleBankPin() then
    osrs.print("Bank PIN entry failed — bind a PIN via the launcher Accounts panel")
    return
  end
end

    To set a PIN for an account, open the launcher's Accounts modal, enter a 4-digit PIN in the "Bank PIN" field, and save. The PIN is encrypted alongside the password and only the bound game tab can read it back (DPAPI user-scope + per-binary entropy salt).

    Method C++ Lua
    Lookup info Bank::info(loc) → BankInfo{x,y,plane,name} —
    Walk to bank Bank::walkTo(ctx, loc) → bool srs.bank.walkTo(loc) → bool

    walkTo returns true once the player is within 6 tiles (ready for Bank::open). Call once per tick — it handles the "already at" / "already walking" cases internally.

    nearestBank is chebyshev distance over the enum tiles. It does not filter members-only / quest-locked banks.

    Open / close¶

    Method C++ Lua
    Open via nearest banker Bank::open(ctx) → bool srs.bank.open() → bool
    Close (X-button) Bank::close(ctx) → bool srs.bank.close() → bool

    open matches bankers by name list (Banker / Banker Tutor / Sigli the Huntsman / Astley / Felkrash) and routes through Interact::perform on the nearest match. Returns false if no banker is in scene.

    Tabs¶

    The bank has 10 tabs: 0 = "All Items" (∞ icon), 1..9 = user-configurable. Current tab lives in varbit BANK_CURRENTTAB (4150). Most scrolling / per-item flows operate on the All Items view — Bank::scrollToSlot auto-switches to it if you're on another tab.

    Method C++ Lua
    Current tab Bank::currentTab(ctx) → int (0..9) srs.bank.currentTab() → int
    Open a specific tab Bank::openTab(ctx, idx) → bool srs.bank.openTab(idx) → bool
    Open All Items (∞) Bank::openMainTab(ctx) → bool srs.bank.openMainTab() → bool

    Tab clicks route as CC_OP (slot 57) packets at widget (12, 10) with subSlot = 10 + tabIndex*4, identifier = 1, itemId = 0xFFFF — matches real-player wire bytes captured 2026-05-19.

    Container reads¶

    Method C++ Lua
    All slots Bank::all(ctx) → vector<InventoryItem> srs.bank.all() → table
    Contains by id Bank::contains(ctx, id) → bool srs.bank.contains(id) → bool
    Contains by name Bank::contains(ctx, name) → bool srs.bank.contains(name) → bool
    Count by id Bank::count(ctx, id) → int32 srs.bank.count(id) → int
    Count by name Bank::count(ctx, name) → int32 srs.bank.count(name) → int

    Name lookups match the item's in-game display name (case- and whitespace-insensitive substring). contains("prayer potion") matches all 4 dose variants because every dose string contains it.

    Bank slot index

    The slot field on items returned from Bank::all is the bank container index (0..hundreds), not a backpack 0..27 index. The container is laid out in tab order — slots [0..N1-1] for tab 1, then [N1..N1+N2-1] for tab 2, ..., then untabbed (tab 0) at the end. The "All Items" visual view renders untabbed FIRST with partial-row breaks between sections — scrollToSlot does the visual-row math for you.

    Scrolling¶

    Method C++ Lua
    Scroll a slot into view Bank::scrollToSlot(ctx, slotIndex) → bool srs.bank.scrollToSlot(slot) → bool
    Mouse-wheel notches Bank::scrollWheel(ctx, notches) → bool srs.bank.scrollWheel(n) → bool
    Raw widget scrollY read — srs.widget.scrollY(g, c) → int or nil
    Raw widget scrollY write — srs.widget.setScrollY(g, c, y) → bool

    scrollToSlot is the high-level helper: it auto-switches to the All Items tab if needed, computes the visual row accounting for tab partial-row breaks, and fires Microbot's trio (setVarcInt(BANK_SCROLL, y) + runScript(UPDATE_SCROLLBAR, ...) + direct IfType+0x88 write). Returns true if the row is already in view (no-op).

    scrollWheel synthesizes WM_MOUSEWHEEL events over the bank center — positive notches scroll DOWN, negative UP. Blocks ~16 ms per notch.

    Per-item withdraw¶

    All variants route a CC_OP (slot 57) packet at widget (12, 12) — Bankmain.ITEMS — with subSlot = bank slot index, itemId from the container at that slot, and the menu identifier per quantity. The caller picks the item by id or by name (case-insensitive partial match).

    Method C++ Lua
    Withdraw 1 Bank::withdrawOne(ctx, id\|name) → bool srs.bank.withdrawOne(id\|name) → bool
    Withdraw N Bank::withdrawX(ctx, id\|name, amount) → bool srs.bank.withdrawX(id\|name, amount) → bool
    Withdraw all Bank::withdrawAll(ctx, id\|name) → bool srs.bank.withdrawAll(id\|name) → bool
    Withdraw all-but-one Bank::withdrawAllButOne(ctx, id\|name) → bool srs.bank.withdrawAllButOne(id\|name) → bool

    Identifier mapping (matches Microbot's Rs2Bank.invokeMenu): - 2 = Withdraw-1, 3 = Withdraw-5, 4 = Withdraw-10 - 7 = Withdraw-All, 8 = Withdraw-All-but-1

    withdrawX amount semantics: - {1, 5, 10} → single packet via fixed identifier (instant) - Any other amount → opens the Withdraw-X prompt (identifier 6), blocks ~1 second while InputManager::typeString types each digit and keyTap(VK_RETURN) submits

    Placeholders (id present, quantity 0) are skipped — withdrawX finds the first slot with a positive quantity.

    Per-item deposit¶

    The deposit-side inventory inside the bank window is widget (15, 3) (Bankside.ITEMS). Clicks route as CC_OP (slot 57) at that widget with subSlot = backpack slot (0..27), itemId from the backpack cache, and Deposit-All identifier 7.

    Method C++ Lua
    Deposit all except (by id) Bank::depositAllExcept(ctx, vector<int32_t>) → bool srs.bank.depositAllExcept({ids...}) → bool
    Deposit all except (by name) Bank::depositAllExcept(ctx, vector<string>) → bool srs.bank.depositAllExcept({"names"...}) → bool

    depositAllExcept fires Deposit-All on the FIRST non-kept inventory slot per call and returns false; the script polls each tick until only kept items remain, at which point it returns true.

    Withdraw quantity preset¶

    Sticky across subsequent withdraw clicks. Mirrors the "1 / 5 / 10 / X / All" button row at the bottom of the bank UI.

    Method C++ Lua
    Set quantity Bank::setWithdrawQuantity(ctx, q) → bool srs.bank.setWithdrawQuantity(q) → bool

    Quantity constants (Bank::Quantity / srs.bank.*):

    Lua const C++ Effect
    ONE Quantity::One Withdraw 1 per click
    FIVE Quantity::Five Withdraw 5 per click
    TEN Quantity::Ten Withdraw 10 per click
    X Quantity::X Prompts for a number (number-entry dialog)
    ALL Quantity::All Withdraw all of stack

    Engineering primitives¶

    For the rare script that needs low-level CS2 access (e.g. invoking a script the bank API doesn't expose), the engine helpers used internally are also bound at srs.engine:

    Lua Description
    srs.engine.setVarcInt(varcId, value) RuneLite setVarcIntValue equivalent
    srs.engine.getVarcInt(varcId) Read a VarClient int
    srs.engine.runScript(scriptId, ...args) Invoke a CS2 script with int args
    srs.widget.address(g, c) Raw IfType pointer for diagnostics
    srs.engine.releaseInputBlock() Diagnostic only — lifts the script's input gate so the user can interact mid-script
    srs.engine.takeInputBlock() Restore the input gate

    Deferred (not yet shipped)¶

    • withdrawAndEquip / withdrawDeficit — convenience over what we have. withdrawDeficit(item, target) would compute target - currentInvCount and call withdrawX with the result.
    • Predicate-based withdraw / deposit — withdrawWhere(filter, n). Needs a callable type bound to both C++ and Lua.
    • Per-item deposit variants (depositOne, depositX, depositAll by id) — same widget + identifier mapping as depositAllExcept but targeting one slot. Trivial follow-up.
    • Bank data cache — event-driven mirror so Bank::all / contains / count work while the bank is closed.
    • Bank search box — type a query into the bank's search field.
