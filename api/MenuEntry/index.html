    MenuEntry¶

    srs::api::MenuEntry / srs.menuEntry

    Typed fluent builder over Interact::doActionRaw. Goes through the same spoof-then-DoAction path as every other facade — fail-closed if the spoofer can't inject.

    Use this when you need raw control over MenuAction params (e.g. while RE'ing a new interaction type) without bypassing the input simulation contract.

    Equivalent to Microbot's NewMenuEntry, minus the option/target text fields (those route through Interact::perform's higher-level path; this builder targets the raw MenuAction dispatch path).

    Example¶

    using srs::api::MenuEntry;
MenuEntry()
    .worldX(10).worldY(20)
    .opcode(/*CC_OP*/ 57)
    .screen(450, 300)
    .fire(ctx);

    local e = srs.menuEntry.new()
e:worldX(10):worldY(20)
 :opcode(srs.menuEntry.CC_OP)
 :screen(450, 300)
 :fire()

    Field semantics¶

    • worldX / worldY — primary param pair. For tile actions these are world tile coords; for inventory / widget actions, worldX is the slot/sub-id and worldY is the encoded widget id.
    • widget(g, c) — convenience that encodes (groupId, childId) into worldY = (group << 16) | child.
    • screen(x, y) — required. Pixel coords of the click target. The spoofer needs these to draw a plausible mouse trail. Sentinel (0, 0) causes the spoofer to skip and fail-closed.
