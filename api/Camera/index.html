    Camera¶

    srs::api::Camera / srs.camera

    Plugin facade vs. GameSDK Camera

    This is the plugin-API facade for camera control. Internal engine access via OSRSClient/GameSDK/Camera.h (low-level state) is not part of the public API — use srs::api::Camera from plugins and scripts.

    Rotation modes¶

    Three "modes" are exposed via three method families:

    Family Mechanism Notes
    rotateTo* Direct write to engine TargetPitch / TargetYaw Instant, no smoothing. Cheap and reliable. Default.
    keyboardRotateTo* Arrow-key holds through InputManager Slower, human-looking. For antiban scenarios.
    mouseRotateTo* DreamBot uses scroll-wheel here OSRS scroll is bound to zoom, not yaw, so this falls back to the direct memory path on this client. Kept for source compatibility with ported scripts.

    Hold duration on keyboardRotateTo* is proportional to angle delta; capped at ~2.5 s per call so a runaway rotation doesn't lock the keyboard for the script.

    Constants¶

    Lua const C++ Value Meaning
    — Camera::kLowestPitch 128 Lowest pitch (nearly horizontal)
    — Camera::kHighestPitch 383 Highest pitch (top-down)
    — Camera::kYawMod 2048 2048 units = 360°

    CameraMode enum (registered at Lua global as CameraMode.*):

    Lua const C++ Notes
    CameraMode.MouseOrKeyboard Mode::MouseOrKeyboard Default — direct memory write
    CameraMode.MouseOnly Mode::MouseOnly Scroll / middle-drag (middle-drag is TODO)
    CameraMode.KeyboardOnly Mode::KeyboardOnly Arrow-key holds

    Zoom is currently broken

    Rotation (default — memory write)¶

    All rotateTo* calls clamp pitch to [128, 383] and mask yaw with & 0x7FF before writing. Return true on a successful write, false if the camera state isn't resolved or the write faults.

    Method C++ Lua
    Both axes Camera::rotateTo(ctx, yaw, pitch) → bool srs.camera.rotateTo(yaw, pitch) → bool
    Yaw only Camera::rotateToYaw(ctx, yaw) → bool srs.camera.rotateToYaw(yaw) → bool
    Pitch only Camera::rotateToPitch(ctx, pitch) → bool srs.camera.rotateToPitch(pitch) → bool
    Face a tile Camera::rotateToTile(ctx, tile) → bool srs.camera.rotateToTile(tile) → bool
    Face an entity Camera::rotateToEntity(ctx, target) → bool srs.camera.rotateToEntity(target) → bool
    Face a tile, interruptible Camera::rotateToTile(ctx, tile, Predicate) → bool srs.camera.rotateToTile(tile, fn) → bool
    Face an entity, interruptible Camera::rotateToEntity(ctx, target, Predicate) → bool srs.camera.rotateToEntity(target, fn) → bool

    Interrupt overloads on rotateToTile and rotateToEntity poll the predicate between micro-steps. Return true from it to abort early (e.g. the player started a fight and the rotation should bail). Lua predicate is any callable that returns truthy/falsy; raising an error in the predicate aborts the rotation cleanly.

    Mouse-rotation family¶

    mouseRotateTo, mouseRotateToYaw, mouseRotateToPitch,
mouseRotateToTile, mouseRotateToEntity

    Same signatures as the rotateTo* family. Falls back to the direct memory path on this client — OSRS scroll-wheel is mapped to zoom, not rotation, and a true scroll-rotate isn't available without middle-mouse-drag support (TODO).

    Keyboard-rotation family¶

    keyboardRotateTo, keyboardRotateToYaw, keyboardRotateToPitch,
keyboardRotateToTile, keyboardRotateToEntity

    Same signatures. Drives the game's arrow-key camera-rotate via InputManager. Slower, human-looking.

    Zoom¶

    Method C++ Lua
    Set zoom level Camera::setZoom(ctx, zoom) → bool srs.camera.setZoom(zoom) → bool
    Fire raw zoom event Camera::fireZoomEvent(ctx, zoom) srs.camera.fireZoomEvent(zoom)

    setZoom injects WM_MOUSEWHEEL events into the game's WndProc until live zoom matches zoomLevel within tolerance. Returns false if the wheel injector or camera state isn't ready, or if zoom didn't converge after ~30 wheel ticks.

    Low-level event firing¶

    Direct, no clamping beyond what the engine itself enforces.

    Method C++ Lua
    Raw pitch+yaw write Camera::firePitchAndYawEvent(ctx, pitch, yaw) srs.camera.firePitchAndYawEvent(pitch, yaw)
    Raw zoom write Camera::fireZoomEvent(ctx, zoom) srs.camera.fireZoomEvent(zoom)

    Event-based rotation (deferred execution)¶

    DreamBot's CameraEvent holds a pending rotation that the caller executes later. Stash one and run it on a different tick.

    Method C++ Lua
    Build "rotate to yaw/pitch" event Camera::rotateToEvent(yaw, pitch) → Event srs.camera.rotateToEvent(yaw, pitch) → Event
    Yaw only Camera::rotateToYawEvent(yaw) → Event srs.camera.rotateToYawEvent(yaw) → Event
    Pitch only Camera::rotateToPitchEvent(pitch) → Event srs.camera.rotateToPitchEvent(pitch) → Event
    Face a tile Camera::rotateToTileEvent(ctx, tile) → Event srs.camera.rotateToTileEvent(tile) → Event
    Face an entity Camera::rotateToEntityEvent(ctx, target) → Event srs.camera.rotateToEntityEvent(target) → Event
    Execute a stored event event.execute(ctx) → bool event:execute() → bool

    Event fields:

    Field Type Notes
    yaw int32 -1 = leave this axis alone
    pitch int32 -1 = leave this axis alone
    zoom int32 -1 = leave this axis alone
    mode Mode Rotation mode

    execute returns true if every set component succeeded; no-op if all axes are -1.

    Example¶

    using namespace srs::api;
if (auto npc = ctx.entityQuery->nearestNpc()) {
    Camera::rotateToEntity(ctx, *npc);
    Camera::setZoom(ctx, 1500);
}

    local npc = entity.nearestNpc()
if npc then
    srs.camera.rotateToEntity(npc)
    srs.camera.setZoom(1500)
end

-- Or build a deferred event and execute next tick:
local pending = srs.camera.rotateToYawEvent(1024)
script.onTick(function() pending:execute() end)
