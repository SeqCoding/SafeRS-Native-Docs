    Outbound packet wire formats¶

    Per-opcode wire formats for the synthetic packets Interact.cpp builds via PacketBuilder. Each variant uses a different byte order + per-byte transform (OSRS per-opcode obfuscation). Live-verified against captured real-player clicks unless noted otherwise.

    Byte transforms¶

    Helper Operation
    byte(n) raw byte
    byteAdd128(n) n + 128 (signed-byte wrap)
    byteSub128(n) n - 128
    shortBE(n) big-endian 16-bit
    shortLE(n) little-endian 16-bit
    shortBE_AddLow(n) BE with lo += 128
    shortLE_AddLow(n) LE with lo += 128
    intBE(n) big-endian 32-bit

    Per-opcode formats¶

    OPLOC1 / 2 / 3 — slots 3 / 4 / 5¶

    Object actions ("Chop", "Bank", "Climb-down", etc.). spawnIndex carries the LocType id. worldX/worldY from DoAction args are scene-relative; wire packet needs world coords (add scene base read from *(GS+0xca40)+0x48/0x4c).

    0x0A OPLOC1  shortLE_AddLow(objId)  byte(ctrl)  shortBE_AddLow(wX)  byte(subop)  shortLE_AddLow(wY)
0x3D OPLOC2  shortBE_AddLow(wX)     shortBE(objId)  byte(ctrl)  byteAdd128(subop)  shortLE_AddLow(wY)
0x46 OPLOC3  shortLE(objId)         byte(ctrl)  shortBE_AddLow(wX)  shortBE_AddLow(wY)  byte(subop)

    ctrl/subop hardcoded to 0 (no modifier, default menu option). If scene base read fails (both 0), bail to Invoke — sending scene-relative coords would walk to (0,0).

    OPNPC1 / 2 / 3 — slots 9 / 10 / 11¶

    NPC actions ("Talk-to", "Attack", "Bank/Trade/Pickpocket"). spawnIndex carries the server NPC index.

    0x6B OPNPC1  byteSub128(ctrl)   byteSub128(subop)  shortLE_AddLow(npcIdx)
0x3F OPNPC2  byte(ctrl)         shortBE_AddLow(npcIdx)  byteSub128(subop)
0x0D OPNPC3  byte(ctrl)         byte(subop)             shortLE_AddLow(npcIdx)

    The original 2-byte-payload version of OPNPC2 (just shortLE_AddLow(npcIdx)) caused silent disconnects ~3s after each bank attempt — the server reads all 4 fields and got garbage for ctrl/subop.

    OPOBJ1 — slot 20 — 0x15¶

    Ground-item Take. spawnIndex carries the item id.

    shortBE(wY) shortLE(wX) byte(ctrl) byteAdd128(subop) shortBE(itemId)

    Object Examine — slot 1002 — 0x39¶

    Two-byte payload: shortBE_AddLow(objId). spawnIndex = object id.

    Ground-item Examine — slot 1004 — 0x14¶

    Six bytes, no ctrl/subop:

    shortBE(wX) shortLE(wY) shortBE(itemId)

    Canvas walk — slot 23 — 0x6F¶

    shortLE(tileY) shortBE(tileX) byte(0)

    Takes WORLD tile coords. doActionImpl args for slot 23 are SCREEN PIXELS — caller must plumb tile coords through tileX/tileY. Without them we bail to Invoke (the engine's raycaster does pixel→tile internally; we can't).

    Minimap walk — slot 1006¶

    Not implemented. The wire packet (0x58) is heavily camera-state-dependent (player pos in 1/128 units, sin/cos-rotated mouse pixel offsets, camera yaw, plus a camera-state pointer chain). The engine's own emitter produces a perfectly-correlated packet when we synthesize a minimap click via CallWindowProcW, so walkToMinimapPoint uses that path in both Invoke and Packet modes.

    Dialog "Continue" — slot 30 — 0x2C¶

    ResumePausebutton. worldY carries the packed widget id, worldX the subChildId (-1 = 0xFFFF for no sub-selection).

    byte(group)  byte(child_hi)  byte(child_lo)  byte(0)  shortLE_AddLow(subChildId)

    IF_BUTTON — slots 57 / 1007 — 0x5B¶

    Widget click. 9 bytes:

    intBE(component)   // (group << 16) | child — comes in as worldY
shortBE(slot)      // inv slot, 0xFFFF = none — comes in as worldX
shortBE(itemId)    // 0xFFFF = none
byte(variant)      // 1..10 action-menu index

    Two caller patterns: - Inventory cell (worldX >= 0): caller MUST supply itemId + variant. Missing → bail to Invoke (engine resolves both from menu state). - No-slot button (worldX == -1, from Widget::click →performWidget): itemId = 0xFFFF, variant = spawnIndex (1 = primary).

    Click pair (disabled)¶

    Earlier iterations had sendClickPair emit synthetic CLICK_1 + CLICK_2 via PacketBuilder with PacketSendHook::suppressNextEngineClickPair swallowing the engine's natural emission. That caused silent server-side disconnects ~2.4s after the OPLOC1 even when wire bytes matched a manual chop byte-for-byte. The engine's CLICK emission must update internal GS state that the server tracks (click counter, hash, sequence — exact field never identified); bypassing it triggers anti-cheat.

    The function is kept as a no-op so call sites compile; the suppress API in PacketSendHook stays for future use if a P2GR-style replacement that ALSO updates engine state is ever built.

    Current architecture: spoofer writes the click slot, the engine's ClickSlotResetHook + dispatcher emit CLICK_1 / CLICK_2 naturally (with saturated 0xFFFE first-short on cold start — P2GR has the same and works). We only send the action packet manually.

    Wire sequence¶

    For action slots that go through perform → primeSpoofForClick:

    MOUSE_MOVE_1 (engine, 14–26 events from spoofer-filled ring)
MOUSE_MOVE_2 (engine, secondary device ring)
CLICK_1      (engine, from kClick1 slot we wrote)
CLICK_2      (engine, from kClick2 slot we wrote)
<action>     (us, drained from PacketSendHook after the engine's CLICK_2 send)

    Drain runs from PacketSendHook after CLICK_2 — running it from PacketStarter puts our packet BEFORE the engine's current one, which desynchronizes sequence numbers (verified by packet captures).

    Param convention by target kind¶

    DoAction's worldX / worldY / spawnIndex carry different things per slot:

    Kind worldX/Y spawnIndex coordType
    Object scene-local tile coords LocType id MANDATORY (MOVUPS-read at +0x20..+0x2F, no null guard)
    Npc scene-local tile coords server NPC idx not read
    GroundItem scene-local tile coords item id not read
    Player scene-local tile coords server player idx not read
    Tile (walk) screen pixels (via walkToScreenPoint) 0 nullptr

    entity arg: pass &{0,0} (a stack-allocated 16-byte slot, NOT NULL) for non-widget arms. The dispatcher's LAB_1400a96d2 cleanup tail can read *(entity+8) unconditionally if GS+0x407148 flag is set; passing a real zero slot makes that safe.

    For widget arms, pass {widget_header_ptr, widget_header_ptr + 0x20} — the engine reads widget body fields via entity[+8].

    Slot dispatch table¶

    Slot Kind Action examples
    3 Object FIRST_OPTION Chop, Mine, Open, Climb-up, Climb-down (most)
    4 Object SECOND_OPTION Bank, Pick, Steal-From
    5 Object THIRD_OPTION Inspect, Collect
    6 Object FOURTH_OPTION
    1001 Object FIFTH_OPTION
    1002 Object Examine
    9 Npc FIRST_OPTION Talk-to
    10 Npc SECOND_OPTION Attack
    11 Npc THIRD_OPTION Bank, Trade, Pickpocket, Travel
    12 Npc FOURTH_OPTION
    13 Npc FIFTH_OPTION
    20 GroundItem Take
    23 Tile Walk
    25 Widget-use
    30 Dialog Continue
    57 / 1007 IF_BUTTON Widget click
    1004 GroundItem Examine

    Per-LocType-id overrides exist for cases where a specific LocType reorders its actions array vs the common case (e.g. id 16684 = three-option ladder). The proper long-term fix is reading LocType.actions[5] live; the override table is a stopgap.

    Minimap walk via WndProc¶

    walkToMinimapPoint synthesizes WM_MOUSEMOVE + WM_LBUTTONDOWN + WM_LBUTTONUP directly to the engine's pre-hook WndProc.

    • OS cursor never moves (CallWindowProcW just delivers messages; doesn't touch the input queue).
    • Game's rendered cursor briefly jumps to the click point, then back when the next real mouse move arrives.
    • Anti-injection: messages from CallWindowProcW don't go through LL hooks, so MSLLHOOKSTRUCT::flags can't flag us via this path.

    We do NOT send a follow-up WM_MOUSEMOVE back to the user's cursor pos immediately — the engine queues click processing for the next tick, and a restore message in the meantime makes the tick processor decide the click isn't on the minimap anymore (walk silently drops).

    Alternatives rejected: - DoAction(slot=1006) — no handler arm. - Direct FUN_14009e4d0 — bails because the menu manager hasn't been populated by the per-tick processor. - SendInput — moves the OS cursor (breaks user concurrent use, breaks multi-client).
