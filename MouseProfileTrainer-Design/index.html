    Mouse Profile Trainer — Design¶

    Date: 2026-06-11 · Status: Proposed · Owner: SafeRSClient (trainer UI) + OSRSClient (runtime model)

    1. Goal¶

    A tool inside SafeRSClient that builds a per-user mouse movement profile from the user's own clicks. The user runs a short session clicking dots of varying size/position; we measure their real motor signature (velocity shape, submovements, lateral bend, launch/landing perturbation, tau braking, mid-drift, OU micro-tremor, LF macro tremor, per-call sigma scatter, overshoot), fit each measurement into a bounded distribution ({mu, sigma, lo, hi}), and save the result as JSON in the client directory. OSRSClient loads that JSON at runtime and samples fresh parameter values per path — so synthesized movement is modeled after the user but never pixel-identical (stable statistical signature, fresh noise per click — same philosophy as the existing MovementProfile comment block).

    Reference: titanclient's "Mouse Path Testing" panel (screenshot 2026-06-11) — its tuning taxonomy (Duration/Fitts, Velocity profile, Submovements, Lateral bend twin-bumps, Launch/Landing perturbation 2D, Tau schedule, Mid-drift Cauchy, OU micro-tremor, LF macro tremor, Hyper per-call sigmas, Overshoot) is the model class we adopt, but we fit it from captured data instead of hand-tuned sliders.

    2. Current state (what this builds on)¶

    • OSRSClient/Input/MovementProfile.h — v1 params-only model: cubic-bezier bow (arcMag, bezierMid1/2), per-sample jitter, overshoot prob/dist, linear Fitts duration, event budget, bimodal dt buckets, click dwell/hold. Seeded per-account via FNV-1a of character name (MovementProfiles::fromSeed). Deliberate property: different accounts → decorrelated signatures. This property must survive (see §8).
    • Consumers: MouseController (per-frame WndProc curve: bezier + easeInOut + jitter + overshoot) and InputSpoofer (ring-writer: event budget + dt buckets). InputManager pushes MovementProfiles::active() before each move; dllmain calls resolveFor() per frame.
    • SafeRSClient = native C++ WebView2 host (main.cpp routes {type:...} JSON messages, nlohmann) + React/Vite UI (ui/src/Launcher.tsx, bridge in ui/src/nativeBridge.ts).
    • Config root: %LOCALAPPDATA%\SafeRS\ (AccountStore already uses ...\SafeRS\accounts).

    4. Capture session (the dot task)¶

    Window: full-stage canvas view in the launcher (game stage hidden via existing set_stage_visible). Dark background, one dot at a time.

    Trial schedule — Fitts coverage grid. Each trial is a (distance D, width W, direction θ) cell: W ∈ {12, 20, 32, 48, 72} px diameter (spans menu rows → inventory slots → big UI buttons), D ∈ {60, 150, 300, 500, 800} px (clamped to window), θ ∈ 8 compass directions. Stratified-random order filling the grid; dot spawns at the sampled D/θ relative to the current cursor position (clamped to bounds; actual D recorded). Defaults: Standard = 120 dots (~4–5 min), Quick = 60, Thorough = 200. Live coverage meter shows unfilled cells.

    Per-trial flow: idle gap 300–700 ms (jittered) → dot appears (spawn timestamp) → user moves and clicks it → ripple feedback → next. The idle gaps and the pre-click hover are first-class data: cursor-at-rest windows are pure tremor signal (voluntary motion ≈ 0), which is exactly where OU micro-tremor and LF macro tremor are estimable without contamination.

    Sampling: pointermove + getCoalescedEvents() (device-rate history, typically 125–1000 Hz in Chromium/WebView2) + pointerrawupdate where available; performance.now() timestamps; coordinates × devicePixelRatio → physical px (what the game's WndProc sees). Preflight screen ("swirl the mouse for 3 s") measures effective sample rate and DPR; warn below ~100 Hz effective. If real-world rates disappoint, fallback is native WM_INPUT capture in the host streamed over the bridge — deferred unless needed.

    Trial rejection (logged, not silently dropped): pointer left canvas / visibilitychange; reaction < 80 ms (anticipation) or movement > 4 s (distraction); inter-sample gap > 50 ms mid-movement (hitch); first 8 trials (warm-up). Misclicks don't advance the dot but are recorded — miss rate feeds landing-sigma sanity and submovement stats.

    Raw trial record (UI → host at session end, or incrementally):

    { "dpr": 1.25, "dot": {"x":812,"y":355,"r":16}, "spawnT": 91234.2, "clickT": 92110.7,
  "press": {"downT": 92110.7, "upT": 92187.3, "button": 0},
  "samples": [[t,x,y], ...] }            // physical px, ms, device-rate

    5. Estimation (trial traces → model parameters)¶

    Preprocess per trial: resample to uniform 4 ms (monotone cubic), Savitzky–Golay velocity/ acceleration, movement onset = speed > 5 % of trial peak sustained 3 samples; chord frame = (along s∈[0,1], perpendicular d). Then per family:

    Family Estimator (per trial → pooled)
    Duration (Fitts) Regress MT = a + b·log₂(D/W+1) across trials → aMs, bMsPerBit; residual spread → duration sigma. R² is a quality gate.
    Velocity profile Normalized v(s): time-to-peak fraction (skew), peak/mean ratio, spectral-arc-length smoothness → shape params of the base minimum-jerk-with-skew profile.
    Submovements Parse velocity local minima after primary peak → count of corrective submovements, amplitude (frac of D), duration; logistic prob vs ID.
    Lateral bend Signed d(s) least-squares-fit to twin-bump basis (two raised-cosine bumps: amp₁,c₁,w₁, amp₂,c₂,w₂). Signed amps capture handedness/curl direction bias.
    Launch perturbation (2D) Heading error angle + magnitude over first ~60 ms vs chord; fitted decay constant. Bias ≠ 0 is a real human signature — keep it.
    Landing perturbation (2D) First-arrival endpoint offset in chord frame → along/across sigmas + bias, scaling vs W.
    Overshoot Chord-axis overrun > W/2 then reversal → P(overshoot
    Tau schedule Deceleration phase: τ(t) = gap/ġap; linear fit slope k (tau-coupling constant; k≈0.5 smooth stop, higher = harder braking) + engage fraction.
    Mid-drift (Cauchy) Residual after removing fitted bend, mid-window s∈[0.2,0.8]; increment distribution fitted by quantile-matched Cauchy scale (robust; tails are the point).
    OU micro-tremor From idle/hover windows: AR(1) on position residuals x[n+1]=αx[n]+ε → θ=−ln α/Δt, σ from ε. Movement-phase high-pass (>6 Hz) residual as cross-check.
    LF macro tremor Idle windows band-pass 0.5–3 Hz → amplitude + dominant freq.
    Hyper per-call sigmas Per-trial residual RMS relative to pooled RMS → lognormal σ of a per-path multiplier. This is the "variance of variance" — some trials careful, some sloppy.
    Click timing dwell (arrival→down), hold (down→up) distributions → replaces v1 clickDelay*/clickHold*.
    Reaction spawn→onset distribution (useful for humanized response delays beyond paths).

    Anti-overfit shrinkage: ~120 trials is thin for ~40 scalars. Every fitted Band is blended toward the neutral default: mu' = w·mu_user + (1−w)·mu_neutral, w = n_accepted/(n_accepted+40) (same for sigma). Quick sessions lean neutral; thorough sessions are mostly user.

    Normalization with retained variance (the core requirement): each scalar is stored as a Band {mu, sigma, lo, hi} where [lo,hi] is the hand-authored global human-plausible range (the analog of titanclient's "client rules"). Fitted mu is clamped into the band; sigma is floored (never 0 — a zero-variance profile is itself a bot tell) and capped. At generation time each path samples clamp(mu + sigma·m_hyper·N(0,1), lo, hi) per parameter — every path differs, but the distribution is the user's.

    6. Generation model (PathModel v2)¶

    generate(from, to, P, rng, bucketMs=0) → timed polyline. Layers, applied in order:

    1. Duration from Fitts Band (D, effective W of the target) → T.
    2. Base kinematic s(t): minimum-jerk position profile warped by velocity-shape params (time-to-peak skew, peak/mean flatness).
    3. Tau braking reshapes the final approach segment per k (blend-in at engage fraction).
    4. Lateral bend: d(s) = Σ twin bumps × D.
    5. Launch perturbation: initial heading/speed error decaying over fitted window.
    6. Mid-drift: Cauchy-stepped walk added in s∈[0.2,0.8], window-faded.
    7. OU micro-tremor (per-axis OU process at sample rate) + LF macro tremor (band-limited sway).
    8. Landing: endpoint drawn from 2D landing covariance; if outside target W or overshoot triggered → corrective submovement(s) (small Fitts moves with their own bend/noise) until inside; overshoot draws pass-distance then returns.
    9. Hyper multiplier m ~ LogNormal(0, σ_hyper) sampled once per call, scaling all noise families (3–11).
    10. Output: ≥ internal 8 ms granularity; optional resample to fixed bucketMs buckets (Simulate parity with titanclient-style invariants); last point == exact target; adjacent duplicates collapsed; clamped to bounds.

    Determinism: rng is injected. Runtime uses fresh random_device per click (per existing v1 philosophy); Simulate exposes a lockable seed for reproducible overlays; golden tests use fixed seeds.

    7. Profile JSON (v2 schema)¶

    %LOCALAPPDATA%\SafeRS\mouse_profile.json (user default) · optional per-account override mouse_profile.<account-slug>.json (slug per AccountStore's slugify). Versioned, CRC'd, unknown fields ignored, every value re-clamped on load (hand-edited files can't go robotic).

    {
  "schema": "safers.mouseProfile/2",
  "createdUtc": "2026-06-11T18:00:00Z",
  "trainer": { "trials": 120, "accepted": 104, "sampleHzMedian": 498, "dpr": 1.25,
               "qualityScore": 0.87, "appVersion": "..." },
  // every leaf below is a Band: {"mu":…,"sigma":…,"lo":…,"hi":…}
  "fitts":     { "aMs": B, "bMsPerBit": B, "durSigmaFrac": B },
  "velocity":  { "timeToPeakFrac": B, "peakOverMean": B, "smoothness": B },
  "submove":   { "extraCount": B, "ampFracOfD": B, "durMs": B, "probPerBit": B },
  "bend":      { "amp1FracOfD": B, "c1": B, "w1": B, "amp2FracOfD": B, "c2": B, "w2": B },
  "launch":    { "angleSigmaDeg": B, "angleBiasDeg": B, "magFrac": B, "decayFrac": B },
  "landing":   { "alongSigmaPx": B, "acrossSigmaPx": B, "alongBiasPx": B, "wScale": B },
  "tau":       { "k": B, "engageFrac": B },
  "midDrift":  { "cauchyScalePx": B },
  "ouTremor":  { "thetaHz": B, "sigmaPx": B },
  "lfTremor":  { "freqHz": B, "ampPx": B },
  "hyper":     { "sigmaLn": B },
  "overshoot": { "prob": B, "distFracOfD": B, "returnMsPerPx": B },
  "clicks":    { "dwellMs": B, "holdMs": B },
  "reaction":  { "ms": B },
  "accountDecorrelation": { "enabled": true, "muShiftFracOfSigma": 0.5, "sigmaScalePct": 15 },
  "legacyV1":  { /* mapped MovementProfile fields — lets v1 consumers run pre-switchover */ },
  "crc32": "…"
}

    legacyV1 mapping ships in phase 1 so the existing MouseController/InputSpoofer immediately inherit user-fitted v1 values (arc ≈ bend amp, jitter ≈ tremor σ, durations from Fitts fit, dwell/hold, overshoot) even before the v2 generator switchover.

    8. Runtime integration (OSRSClient) & per-account decorrelation¶

    • MouseProfileStore::resolve() runs at injection and inside MovementProfiles::resolveFor (name-change path; add cheap mtime re-stat so re-saving from the trainer takes effect on relog, no client restart). Precedence: per-account JSON → user JSON → v1 fromSeed(name). Any parse/validation failure → log once, fall back; input must never hard-fail.
    • Keep cross-account decorrelation. A single shared user JSON would make all of a user's accounts emit one identical statistical fingerprint — exactly what v1's FNV-1a seeding was built to prevent (linkage risk). Default-on: account seed shifts each mu by up to ±0.5·sigma (within band) and scales sigma ±15 %. Same human style-envelope, different individual per account. Toggleable in the JSON for users who insist.
    • Consumers: MouseController::generateTrajectory swaps bezier/easeInOut/jitter for a PathModel polyline (per-frame update() interpolates it; WndProc emission + AFK-timer touch unchanged). InputSpoofer resamples the polyline into its event budget/dt-bucket ring format. Both behind a pathModelV2 kill-switch defaulting off until A/B'd.

    9. Trainer UI (three tabs in the launcher)¶

    Capture — preflight (sample-rate/DPR calibration) → dot session with progress bar, live coverage grid, accepted/rejected counters, abort/pause. Review — per-family cards: fitted mu ± sigma rendered inside the [lo, hi] band bar, shrinkage weight, quality gates (Fitts R² ≥ 0.5, accepted ≥ 50, sample rate ≥ 100 Hz…), warnings ("trackpad-like signature: tremor floor clamped"), then Save / Set active / Save as account override. Simulate — click two points on a canvas (or randomize), N = 1–200 paths (user-configurable), optional seed lock, bucket-ms control; renders overlaid polylines + a batch table (mean/σ/min/max of point count, duration, arc length, straightness, avg/peak speed, lateral dev, overshoot rate) + invariant checklist (exact target, bucket spacing, bounds, adjacent-distinct, monotonic t) — deliberately mirroring the titanclient panel — plus "vs. my real trials": overlays captured trials of similar D/W and shows per-metric percentile chips ("synth peak speed = p43 of yours").

    Bridge messages (all host-side handlers in main.cpp, work off the UI thread): mouse_trainer_fit {trials[]} → mouse_trainer_fit_result {profile, diagnostics} · mouse_trainer_generate {profile?, from, to, n, seed?, bucketMs} → mouse_trainer_paths {paths[][], metrics, invariants} · mouse_profile_save / list / load / set_active → correspondingly-named replies. Raw session is also dumped to %LOCALAPPDATA%\SafeRS\profiles\sessions\<ts>.json.gz so fits can be re-run after estimator improvements without re-clicking.

    10. Phasing¶

    1. PathModel lib + schema + golden tests (no UI): generator, ProfileJson, neutral profile, invariant tests, legacyV1 mapping. Synthetic-profile sanity via existing DebugPanel. [DONE 2026-06-11] — OSRSClient/Input/PathModel/ (PathMath/PathParams/PathModel/ ProfileJson/Estimators/PathModelSelfTest), DebugPanel Path Lab tab, standalone runner OSRSClient/tools/pathmodel_tests/build_and_run.ps1 (39 tests green, incl. estimator round-trip). Gotcha: Profile::hyper had to be hyperVar — rpcndr.h #define hyper __int64 leaks through the DLL PCH.
    2. Trainer UI: capture + fit + save through the bridge; Review/Simulate tabs. [DONE 2026-06-11] — SafeRSClient/MouseTrainerHost.{h,cpp} (compiles the shared ..\OSRSClient\Input\PathModel\*.cpp + MovementProfileNeutral.cpp; verbs mouse_trainer_fit / mouse_trainer_generate / mouse_profile_{save,load} / mouse_trainer_session_save, atomic write to %LOCALAPPDATA%\SafeRS\mouse_profile.json), bridge wrappers in nativeBridge.ts, ui/src/MouseTrainer.tsx (Capture/Review/Simulate), dock entry. Both binaries build clean; UI renders + is interactive (verified in vite preview + by the user manually). Bug found & fixed during smoke test: the capture surface cached its getBoundingClientRect right after the phase flip to "running", but the status row grows taller in running mode and shifts the surface down after the cache — so every dot-click mis-tested against a stale vertical offset. Fix: read the rect live per pointer event (liveRect()), never cache. (Note: synthetic PointerEvents don't drive React's pointer handlers in the headless preview — only .click()/onClick does — so the dot-hit path must be verified with real mouse input, not the preview harness.)
    3. Runtime loader + MouseController v2 switchover behind kill-switch; A/B with spoof logs. [DONE 2026-06-11] — OSRSClient/Input/MouseProfileStore.{h,cpp} loads %LOCALAPPDATA%\SafeRS\mouse_profile.json via pathmodel::parse, caches + re-stats mtime in resolveFor (picks up trainer re-saves on next frame), applies name-seeded decorrelate, fail-soft on parse error. Runtime kill-switch enabled() (default off). MouseController::setProfileV2 + moveToV2/updateV2Locked: when the switch is on and a profile is loaded, moveTo synthesizes a full pathmodel::generate polyline and update interpolates it by timestamp — bypassing bezier/overshoot/jitter (all baked into the path). v1 path untouched when off. InputManager::clickAt pushes the v2 profile+predicate; dllmain resolves the store each frame after MovementProfiles::resolveFor. DebugPanel Input tab has the toggle + load/quality/seed status (the A/B control). Thread-safety: clickAt→moveTo runs on the Lua worker thread, update on the render thread; the v1 POD control points tolerate that race but the polyline std::vector can't, so all v2-playback fields are serialized by m_v2Mtx (publish under lock, flip m_moving after). Click delay/hold still come from v1 — wiring v2 dwell/hold is a phase-4 follow-up, as is per-target width (currently a fixed 8px radius) and the per-account override file.
    4. InputSpoofer switchover, per-account overrides UX, decorrelation polish. [DONE 2026-06-11] — (a) InputSpoofer::inject samples ring positions from the v2 polyline (MouseProfileStore) instead of bezier+decelEase when the kill-switch is on, and takes duration from the polyline (clamped to the ring's [60,320] window); the ring budget, bimodal dt timeline, secondary-ring mirror and click-staging are unchanged, and it fail-softs to v1 on an empty path. With the switch OFF (default) both paths are byte-for-byte the old v1 behavior. (b) v2 click dwell/hold: MouseController::v2ClickTiming hands InputManager the fitted dwell (arrival→down) and hold (down→up) for the click states; v1 bands otherwise. (c) per-target width: optional targetRadiusPx threaded through clickAt→moveTo→moveToV2 and SpoofRequest, and derived from the target's real on-screen bounds — Camera::footprintRadiusPx projects 1-tile neighbours → screen px-per-tile, scales by the footprint, takes the tighter dimension, clamps [4,60]; object/NPC/player (perform) and widget WndProc (clickReal*, from the rect) pass real radii, so near/large targets read as easier and far/small as precise. 8px default only where bounds are unknown (bare clickScreen, short widget-button DoActions where Fitts sits near the floor anyway). (d) per-account override: MouseProfileStore prefers mouse_profile.<charslug>.json (used as-is — already account-specific) over the shared mouse_profile.json (decorrelated by name); DebugPanel flags which is active. Launcher "save for this account" UX is the remaining bit (the load/precedence side is live). DLL builds clean, 42 lib tests green.

    Status: all four phases shipped. The trainer captures→fits→saves a profile, and both in-game movement paths (WndProc curve + ring-writer) consume it behind the pathModelV2 kill-switch. Remaining polish: launcher "save override for account" UX and persisting the kill-switch in Config.

    11. Risks / open questions¶

    • WebView2 effective sample rate on low-end mice/VMs — preflight measures it; WM_INPUT native capture is the fallback. Pointer coords must be DPR-corrected or tremor σ is ~25 % off.
    • Trackpad/pen users produce non-mouse signatures (no 8–12 Hz tremor, speed caps) — detect via tremor spectrum and warn; clamps prevent degenerate profiles either way.
    • Profile sharing between users would clone fingerprints — discourage (per-account decorrelation already softens it; could salt exports later).
    • Staleness: human signatures drift; nudge re-capture after ~60 days (metadata has the date).
    • Open: should the trainer also fit wheel/scroll and key-timing profiles later? Same capture-fit-band machinery applies.
